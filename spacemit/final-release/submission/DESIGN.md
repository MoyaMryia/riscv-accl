# 框架改造与模型加工设计

## 设计目标

目标是在 K1 上用同一生产构建改善两个模型的预填充、解码与长上下文性能。
实现基于 SpaceMiT `llama.cpp` 固定提交 `a990751d55a4c54acf2bb77d44282c2093652359`。
完整改动位于 `runtime/package/unified.patch`。
生产版本为 `k1-final-20261013-r3`。
编译默认值位于 `ggml/include/spine-k1-defaults.h`，选择记录位于 `runtime/package/default-policy.json`。

## 最终启用路径

| 改造 | 主要代码 | 行为与边界 |
| --- | --- | --- |
| 宽 RVV 注意力 | `ggml/src/ggml-cpu/spacemit/rvv_kernels.cpp` | 使用 K1 向量路径；保持 F16 K/V 与主输出精度。 |
| IME route 3 | `ggml/src/ggml-cpu/spacemit/ime.cpp` | 改变已支持矩阵乘形状的分派；不支持形状保留回退路径。 |
| B1-r2 组内注意力 | `ggml/src/ggml-cpu/spine-k1-local-attention.h` | 同组查询头复用 K/V 加载，使用线程独立临时区；形状与边界不匹配时回退。 |
| C1 状态卷积 | `src/models/spine-k1-ssm-conv.h`、`ggml/src/ggml-cpu/spine-k1-ssm-kernel.h` | 调整状态卷积路径；保持状态与重置语义并检查回退。 |
| 固化默认配置 | `common/arg.cpp`、`common/common.h`、`tools/server/server-context.cpp` | 固定四线程、批大小 32、上下文 12288、单槽及 F16 缓存。 |

默认候选掩码为 3，启用 B1-r2 与 C1。
C2-r2 代码保留但默认关闭。
选型对两个模型、预填充和解码等权。
冻结搜索共 104 次请求，参数阶段保留四线程及批大小 32。
掩码 7 的观测得分最低，掩码 3 位于冻结的 3% 未决区间内。
规则在该区间内优先选择较少候选，因此采用掩码 3。
该规则不证明所有负载上的全局最优。

## 起点与收益解释

起点提交为 `5ad05d8796cb094ee23a3a0152874f8a2b3060f8`。
兼容处理只移除 K1 无法构建的 IME2 源文件项，并修正未启用草稿头的宽度加载。
起点主计算图与计算内核保持原字节。
两臂使用相同权重、精度、输入、输出历史和运行依赖。
性能收益覆盖原始软件状态到最终软件状态的变化。
最终版完成一次请求的速度，2B 为起点的 1.24～3.59 倍，4B 为起点的 1.41～4.72 倍。
输入越长，倍数越大；服务器内存两臂之差小于 3 MiB。
逐形状数据见 `reports/SUBMISSION-ZH.pdf` 第 5 节。
它不单独归因于某一个内核，也不包含历史量化变化的收益。

普通对照报告覆盖 512、2048 和 8192 输入。
16k／32k 补测使用同一二进制，只扩大上下文容量。
各候选的独立收益不能相加或相乘。
旧组合的退化、失败默认值与未采用方案仍保留原证据。

## 正确性与失败保留

原 r3 通过 104 项路由、95 项注意力、432 项 SSM 和 158 项 GDN 算子检查。
转储哈希与已核验参考一致。
两个模型的 64 条短状态全词表记录逐位一致。
这些状态记录使用上下文 4096 与短前缀，不能替代长状态验收。
六次自然代码回答通过固定功能检查。
长输入性能请求为 16384 输入每模型 2 对，32768 输入每模型 1 对。

r1 因 GPU 默认值检查失败而终止。
r2 修正该问题后仍出现自动四槽行为。
r3 在服务器初始化处固定单槽，并完成重新构建与迁移启动核验。
这些失败记录必须随证据保留。
旧全组合相对 B1 的 4B/2048/65 解码退化 3.0220477%，仍只适用于原测量条件。
IME 标量调度候选因初筛失败而排除。

## 模型压缩与未实现内容

现用模型采用 Q4_0 权重和 Q4_0 词嵌入。
历史加工追加 MTP 张量及草稿头，但最终默认使用直接解码。
不把标准 Q4_0 量化描述为本项目提出的新量化算法。
完整官方转换仍待实际验证。
本次性能对照不改变权重，也不测量模型压缩带来的收益。

本发布没有实现 GPU 加速、KV 压缩或分页内存收益。
TCM 用户态库可用不证明模型缓冲区使用真实 TCM。
旧独立硬件测试不能作为本次模型推理收益。
固定多轮质量与长状态验收仍有缺口。

## TCM 用户态工具与当前路径

已实现：`tools/tcm/` 提供状态、块申请、边界检查、读写和自动释放。
已验证：10 项本地夹具检查通过，板端申请明确拒绝无权限的硬件访问。
已验证：原 r3 的两模型短推理没有成功打开或映射 `/dev/tcm`。
该工具未接入生产推理图，不能记为新的模型优化收益。
完整记录见[调查报告](../reports/2026-10-16-final-release-tcm.md)。
