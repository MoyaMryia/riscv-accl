冻结时间：2026-10-09 22:35，Asia/Singapore。

原 core 保存的函数对象地址为 `0x3f8554eac0`。
其偏移 104 的字段值为 `0x6a8a28`。
返回地址前的指令从该字段读取参数。
故障寄存器中的参数却为 `0x6a0028`。
该差异尚不能证明硬件故障。
原 core 没有保存对应的可执行代码页。
当前 ELF 首页面与原 core 相同，但不能替代历史全文件哈希。

诊断必须在新子目录、tmux 和原共用锁内执行。
必须使用与调用指令相同的 `c.ld a0,104(s1)`。
每次只运行一个原生进程。
每个进程使用 16 MiB 数据。
依次绑定 CPU 0～7，固定种子 42，各执行 64 遍读取。
每个字段值同时包含原观察值和固定整数模式。
每次读取必须与预期值比较。
每个 CPU 最长 120 s，整个诊断最长 1200 s。
出现差异时必须停止后续 CPU，并保存地址、预期值、实际值及再次读取值。
必须保存源码、可执行文件、反汇编、运行库哈希及退出状态。
不得改变频率、系统配置、模型或候选代码。

此诊断只检查固定指令和固定内存模式。
全部通过不能排除罕见瞬态故障，也不能确定原 Python 错误的根因。
