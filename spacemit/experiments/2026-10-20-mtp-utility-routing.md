# MTP 收益路由规范

日期：2026-10-20，Asia/Singapore。
状态：规范，待启动。
本规范固定下一阶段的假设、数据、门禁与记录方式。
启动后本文件不再改写；执行偏差写入新记录。

## 1. 目的

目标：让多词元预测（MTP）只在净快的请求上启用。
主指标为一次请求的完整时长。
次指标为首词元时延、解码耗时与输出词元数。
质量与速度分开判定。
生产默认在验收通过前保持直接解码。

## 3. 定义

收益标签：同一请求在直接与 MTP 两臂的完整时长差。
节省为正表示 MTP 更快。
配对差按同题、同轮、同输入计算。

oracle：对每个配对请求选择较快的实验臂，再求和。
oracle 有三个粒度：逐请求、逐任务家族、逐类别。
逐请求 oracle 是本项目的收益上限。
逐类别 oracle 用于复现现有路由策略。

窄策略：只对家族级 oracle 达到门槛的代码家族启用 MTP，其他请求走直接解码。

净收益：路由后的总时长相对全直接的总时长变化。
净收益扣除分类器与代理开销。
探针浪费的草稿词元计入 MTP 臂成本。

## 4. 阶段 0：计数口径修复

原生计数必须分离原始提案与恢复回放。
接受率使用原始提案的生成数与首次接受数。
恢复后的队列长度等于上一事件接受数加 1。
低接受率回退只统计原始提案窗口。
回退阈值与窗口长度在实现前写死，不在测量中调整。

验收：
- 用历史真实 trace 重放，接受率与恢复比例与既有复算一致。
- 注入低接受率请求，回退在窗口内触发。
- 注入高接受率请求，回退不触发。
- 回退触发后，后续请求恢复默认起草状态。

不通过则停止本规范后续阶段。
理由：在线门控读取同一计数，口径错误会使门控方向相反。

## 5. 阶段 1：离线 oracle

输入为已完成批次中保存的完整记录。
来源批次：81 次追踪、通用 36 次、完整词表 12 次、路由 24 次、代码控制 12 次、发现批次已完成的配对。
只使用三臂齐全的配对。
截断、超时、传输失败的请求不进入配对。

计算：
- 每配对请求的直接时长与 MTP 时长。
- 逐请求 oracle 净收益。
- 逐家族 oracle 净收益。
- 逐类别 oracle 净收益。
- 按任务家族聚类的 bootstrap 95% 区间，重采样 10000 次。

通过条件：逐请求 oracle 点估计不少于 5%，且区间下界大于 3%。
区间下界不超过 3% 时停止项目，结论记为负结果。

窄策略条件：至少一个代码家族的家族级 oracle 净收益不少于 3%。
通过时输出启用家族集合与对应净收益。
没有家族达到 3% 时停止项目。

## 6. 阶段 2：预测器

特征分三层。
零成本层：输入词元数、语言、代码块、任务模板词、家族 n-gram。
低成本层：前缀词表覆盖率、提示与草稿词的 n-gram 命中率。
高成本层：BERT 向量，只作对照。

模型：逻辑回归与梯度提升各训练一次。
标签：MTP 相对直接节省不少于 5% 的请求为正类。
损失按毫秒加权，不按准确率加权。
切分按任务家族分组，训练集与留出集不共享家族或文本。

决策规则：
- 预测节省大于分类成本加 2 个百分点时选 MTP。
- 否则选直接解码。
- 分类成本用实测值，不写估计值。

通过条件：
- 留出集正类 precision 不少于 0.6。
- 预测总净收益不少于 2%。
- 误判为 MTP 的请求平均损失不超过 5%。

不通过则停止在线阶段，保留预测器与负结果。

## 7. 阶段 3：在线门控

在线门控在独立实验构建中实现，不进入生产默认。
结构为两段式。
第一段：请求前按阶段 2 的规则选择实验臂。
第二段：MTP 请求执行前 K 步探针，用原始接受率决定继续或停止起草。
停止起草后，请求其余部分使用直接解码，输出不截断。

探针参数：
- K 取 8 到 16 步，启动前固定。
- 每请求浪费上限为 100 个草稿词元。
- 超过上限立即转直接解码。

代理与控制器共用逐请求文件锁。
分类、探针与代理耗时计入完整请求时间。

退化中止：连续 3 行相同且每行不短于 20 个字符时停止该请求，记 `incomplete/degenerate_repetition`。
守卫先对连接执行 `shutdown`，再关闭响应；服务端在下一次写入时看到断连并停止生成。
不带会话标识的请求，服务端停止条件就是连接存活检查；源码位置为 `server-stream.cpp:622`。
退化请求的空闲等待上限为 120 s，其他请求保持 30 s。
守卫不改服务端采样参数。

注入测试：
- 低接受率请求在探针后转直接，完整回答不截断。
- 连续重复行在第三次出现时停止请求，并保留已生成文本。
- 回放计数异常不改变门控决定。
- 分类器超时只影响该请求，返回明确错误。
- 探针进程崩溃只使该请求失败，后续请求继续。

## 8. 阶段 4：冻结验收

新题在首次推理前冻结，且不复用旧题。
作者与实现者分离，参考答案先独立核对。

| 类别 | 题目数 | 每题配对 | 请求数 |
| --- | ---: | ---: | ---: |
| 代码（5 家族×3 变体） | 15 | 3 | 90 |
| 中文 | 3 | 2 | 12 |
| 问答 | 3 | 2 | 12 |
| 长文 | 3 | 2 | 12 |
| 合计 | 24 | — | 126 |

另加 2 次预检请求。
批次预算 25200 s，超时停止本批并保留记录。
批次在 tmux 中持有共用锁。
全部请求自然停止，输出上限 4096 词元。
缓存复用必须为 0。

验收集同时包含启用家族与未启用家族。
未启用家族的请求必须走直接解码，且预测器不得选 MTP。
启用家族按预测规则执行。

质量：
- 代码题执行既有 106 项独立检查。
- 非代码答案隐藏实验臂名称，交独立盲审。
- 出现新的事实、引用或代码错误即失败。
- 质量均分相对直接解码的损失不超过 0.25。

采纳门禁：

| 门禁 | 条件 |
| --- | --- |
| 总时长 | 净收益不少于 3% |
| 每类减速 | 不超过 3% |
| 质量 | 无新错误，均分损失不超过 0.25 |
| 分类开销 | 已计入，且不超过实测上限 |
| 失败计数 | 失败、超时、截断、阻断均为 0 |

统计：按任务家族聚类 bootstrap，比较路由与全直接的总时长差。
点估计不少于 3%，区间下界大于 0 才算通过。

任一条件不通过时，记录负结果，生产默认保持直接解码。
通过时，候选进入默认路径，并保留手动覆盖头与一键回退。

## 9. 记录与失败隔离

每个批次使用新目录，不覆盖已有记录。
保存请求、完整回答、SSE 原始字节、日志切片、退出状态与失败原因。
退化中止单独记为 `degenerate_repetition`，不与输出上限混用。
单次失败只停止该尝试。
其余独立请求继续执行。
不完整配对不进入速度均值。
批次结束时报告 passed、failed、incomplete、blocked、unattempted 数量。
任一非 passed 状态使批次非零。
只保留一份协议与一份原始记录，不改写历史批次的文件。

## 10. 风险与缓解

| 风险 | 缓解 |
| --- | --- |
| 探针成本抵消收益 | 固定 K 与浪费上限；探针阶段计入成本 |
| 接受率分布随题目变化 | 按家族分组切分；验收使用新题 |
| 分类器开销过大 | 优先零成本特征；BERT 只作对照 |
| 恢复回放成本主导 | 阶段 0 先修复计数，再测回退 |
| 长文单对观测 | 验收每题两对，长文补到三对 |
| 结果受单批次影响 | 家族聚类区间；不过门禁不采纳 |

## 12. 不做的事

不改 BERT 权重去拟合速度。
不在发现阶段改生产默认值。

不把不同基线的百分比相加或相乘。
不在本阶段测试 4B。
