## 1. 交付目标

输入为实际二进制、输入数据、线程配置和运行条件。
模型在其他机器上预测 K1 的执行周期。
模型进一步估计指定运行条件下的耗时。
模型比较两个实现的收益。
模型指出瓶颈、适用范围和证据缺口。
模型给出下一项最有价值的补测实验。

最终报告必须回答以下问题。

1. 哪些改进更值得投入？
2. 收益主要来自哪项执行机制？
3. 哪些输入、缓存状态或线程配置会改变判断？
4. 当前证据能分辨多大的收益？
5. 哪项未知参数最可能使结论反转？
6. 需要哪项板端实验才能缩小不确定性？

全部候选均保留。
不设置性能淘汰门槛。
模型能力验收与候选优先级分开记录。
模型能力未通过验收时，报告必须保留失败结果。

## 2. 当前基础与缺口

已实现：实际二进制轨迹、依赖分析、分项周期估计和访存场景重放。
已实现：固定算子的形状模型、误差校准、后测和便携重放。
已验证：部分用户态周期事件和分项实验。
这些能力可以复用为测量、轨迹和归档底座。
它们尚未构成经过独立验证的完整 CPU 模型。

[V7 报告](../reports/2026-10-12-k1-model-v7.md)记录混合 IME 的预测失败。
该报告的点预测方向符号一致性为 9/27。
冻结区间覆盖 27/27 个版本，但区间很宽。
这项覆盖不能证明模型可以安排优化投入顺序。

[算子模型 V1 报告](../reports/2026-10-12-k1-operator-model-v1.md)记录固定算法对的形状后测。
IME 的方向一致为 18/18。
卷积的方向一致为 16/18。
卷积还有一个形状组超出冻结界限。
这些结果不能证明新算法的预测能力。

后续必须把已有算子作为集成检查材料。
已公开的后测结果不能再次称为新模型的独立后测。
新的独立检查必须使用未参与模型选择的代码族与测量批次。

## 3. 模型结构

### 3.1 快速模型

快速模型以实际二进制和动态轨迹为输入。
核心状态包括取指、发射、寄存器就绪、执行资源、访存队列和缓存状态。
模型按指令顺序推进状态。
模型必须表达并行执行与资源冲突。
不能把存在重叠的成本直接相加。

LLVM 的 [X60 调度模型](https://github.com/llvm/llvm-project/blob/main/llvm/lib/Target/RISCV/RISCVSchedSpacemitX60.td)采用顺序双发射配置。
源码说明其依据包含其他处理器资料和实机实验。
源码也保留未确认参数和资源假设。
首次使用时必须固定上游提交与文件散列。
这些参数作为待检验的起点。
本项目必须单独验证目标板上的有效时序。

GCC 也提供 X60 的资源预约描述。
固定源码与语法核对见第七轮报告。
资源预约、结果延迟与操作数旁路必须分开解释。
资源名称数量不能直接代表硬件端口数量。
现成模型与自建模型均必须保留失准结果。

### 3.2 详细模型

详细模型用于检查快速模型难以表达的机制。
候选实现包括项目专用事件模拟器和 gem5 的 Minor CPU 模型。
[Minor 官方说明](https://www.gem5.org/documentation/general_docs/cpu_models/minor_cpu)将其定义为可配置的顺序处理器模型。
选型前必须检查目标版本的 RISC-V、向量扩展和 IME 支持。
必须先通过实际二进制的数值检查。
必须再通过相同测量协议下的周期检查。

能执行程序不表示完成 K1 标定。
模型更详细也不表示预测更准确。
后端比较必须同时报告误差、覆盖范围和主机计算成本。
不能直接用默认乱序核参数代表 K1。

### 3.3 任务级模型

任务级模型组合算子、线程同步和实际调用关系。
输出包括关键路径、任务耗时和整体收益。
关键路径指决定任务完成时间的依赖路径。
CPU 采样占比不能直接替代关键路径时间。
该层必须使用真实调用次数、输入形状和线程分工。

## 4. 阶段与验收证据

| 阶段 | 必须完成的工作 | 交付与验收证据 |
| --- | --- | --- |
| P0：平台与测量 | 核对核、簇、扩展、计数器、频率、温度和测量范围。 | 平台资料包、计数器审计、跨时段配对测量。 |
| P1：标量与前端 | 识别顺序发射限制、双发射配对、依赖延迟和分支成本。 | 参数证据表、第一版单核状态模型、保留循环后测。 |
| P2：向量与 IME | 识别向量状态成本、寄存器约束和混合执行资源竞争。 | 组合实验、数值检查、混合循环预测报告。 |
| P3：存储层次 | 识别缓存、地址转换、预取、并发访存和写入行为。 | 访存状态模型、工作集边界实验、独立访存后测。 |
| P4：单核真实代码 | 组合前三层，评估未参与拟合的代码改进族。 | 新算法后测、收益误差、排序价值和适用范围。 |
| P5：多核与同步 | 识别簇内、跨簇竞争和线程关键路径。 | 多核模型、同步轨迹、实际任务后测。 |
| P6：工具成熟度 | 完成自动诊断、补测选择、便携重放和详细后端比较。 | 可复现评估包、失败语料、主机成本报告。 |

独立检查设计从 P0 开始。
P4 不能等模型完成后才选择检查代码。
P6 的基础归档工具随前面各阶段交付。
详细后端探索可以提前进行小规模功能检查。
大规模后端开发必须有明确的误差来源和对照实验。

## 5. P0：先建立可信的观测条件

### 5.1 平台范围

记录内核、固件、编译器、扩展、CPU 编号与簇映射。
记录缓存与内存配置。
逐核检查实际可执行的扩展。
不能把 CPU 0 的资料直接复制到所有核。

[厂商 K1 资料](https://github.com/spacemit-com/docs-chip/blob/main/en/key_stone/k1/k1_docs/k1_ds.md)区分两个 CPU 簇的 AI 扩展能力。
板端实验必须核实操作系统编号与这些簇的对应关系。
多核 IME 计划不能默认八个核均有相同能力。
紧耦合存储器（TCM）的可访问性必须单独核实。
未使用 TCM 的实验不能说明其性能收益。

### 5.2 计数器与时间

审计性能监测单元（PMU）的事件语义和权限。
分别记录用户态周期、线程 CPU 时间与墙钟耗时。
核对用户态过滤、内核态过滤、计数器宽度和复用行为。
使用已知循环长度检查事件变化关系。
保留无法审计的事件，并标为待验证。

已有原始事件 0x22 的用户态审计可以作为目标配置下的证据。
该结论不能自动推广到其他事件、内核或板卡。
频率快照不能证明测量期间频率恒定。
必须记录频率变化、温度、迁移、中断与后台负载的可观测信息。
缺少观测项时必须保留限制。

### 5.3 实验协议

先检查已有任务和共用锁。
正式批次在 tmux 中全程持有共用锁。
固定线程亲和性与输入数据。
交错安排基线与候选。
跨独立会话重复配对测量。
数值检查必须覆盖实际有效输出。

记录计时开销、循环次数和样本时长。
不能用短样本的波动代表预测误差。
需要临时修改运行设置时，必须记录原值和恢复结果。
未获授权的系统服务、内核和固件变更不属于本计划的默认动作。

## 6. P1：标量执行与前端

必须区分结果延迟、持续吞吐和资源占用时间。
依赖链用于检查结果延迟。
独立链用于检查持续吞吐。
混合指令用于检查共享资源。
插入间隔的实验用于检查阻塞与旁路。

必须覆盖以下问题。

- 指令对能否同周期发射，以及指令顺序是否改变配对。
- 整数、浮点、加载、存储和分支之间的配对限制。
- 前项阻塞时，后项指令能否继续推进。
- 不同生产者与消费者之间的寄存器就绪延迟。
- 写后读、写后写和读后写依赖的实际限制。
- 长延迟操作对其他执行资源的影响。
- 取指对齐、压缩指令比例和循环体长度的影响。
- 指令缓存容量、冲突与跨行取指的影响。
- 分支方向、目标、间接跳转和函数返回的影响。
- 寄存器压力与溢出访存的影响。

参数表必须保留单位、条件、证据路径和替代解释。
一次指令对实验不能证明真实硬件端口数量。
多个机制解释同一结果时，必须设计能区分这些机制的实验。
仍无法区分时，模型必须保留多组有效假设。

## 7. P2：向量与 IME

RISC-V 向量扩展（RVV）的参数不能只按操作码分类。
必须覆盖元素宽度（SEW）、寄存器组倍率（LMUL）和有效元素数（VL）。
必须检查尾部、掩码和向量状态切换。
必须检查缩窄、扩宽、归约、重排与索引操作。
必须检查连续、跨步、索引和分段访存。
必须区分逻辑向量宽度与实际执行吞吐。

整数矩阵扩展（IME）的检查必须包含依赖链和独立链。
必须检查寄存器组复用、输入加载与点积之间的时序。
必须检查标量、RVV 和 IME 的组合。
实验必须区分数据依赖、资源竞争和前端阻塞。
固定输入数值检查不能推广到任意输入。
新增数值用例必须覆盖边界值、符号与累加范围。

V7 的失败模式用于提出新实验假设。
新的模型修正必须使用新批次。
V7 的原始模型、界限与失败结果保持不变。

## 8. P3：缓存、内存与地址转换

先检查工作集大小、对齐、步长、访问顺序和并发流数量。
分别测量依赖指针链与独立访存流。
前者不能单独代表纯内存延迟。
后者不能单独代表全部算法的可用带宽。

必须覆盖以下机制。

- 一级数据缓存（L1D）与二级缓存（L2）的命中成本和容量边界。
- 缓存行大小、组冲突、替换行为与写分配。
- 未完成请求数量与可重叠的访存。
- 存储缓冲、写回、存储到加载转发与部分地址重叠。
- 预取对步长、距离和并发流数量的响应。
- 地址转换缓存（TLB）、页大小和页表访问。
- 缺页、首次接触与预热状态。
- 计算与访存重叠，以及队列反压。
- 内存频率与持续负载对延迟、带宽的影响。

只有虚拟地址时，必须保留物理地址映射的未知项。
驱逐缓冲区不能自动证明缓存完全冷却。
必须给出初始缓存状态的证据或场景假设。
缺少流量计数器时，不能把重放的缺失数称为实测内存流量。
不能把全部缓存缺失乘以固定延迟后直接加到计算周期。

## 9. P4：形成可检验的单核模型

模型拟合必须同时检查周期与已审计的事件。
必须检查参数敏感度和参数间的替代关系。
灵敏度检查必须指出哪些参数会改变收益方向。
训练数据不能只包含孤立指令。
训练数据必须包含机制已知的组合循环。

轨迹必须保留控制流、向量状态和有效访存。
必须识别截断轨迹与未记录的区间。
循环采样必须保留预热与循环间状态。
模型不能利用真实处理器尚未获得的信息提前发射访存。
修改算法或输入后，必须重新核对实际路径。
旧轨迹不能代表变化后的控制流。

独立检查按代码改进族分组。
候选族包括展开、指令重排、分块、打包、布局、融合与向量化。
必须保留整个改进族，而非只保留同一代码的几个形状。
还必须保留不同编译结果、输入分布与工作集条件。
模型选择完成后冻结参数。
误差校准完成后冻结界限。
最终后测失败不能用于修改本轮已声明结果。

## 10. P5：多核与任务耗时

首先区分簇内共享与跨簇共享。
按实际核能力设计 1、2、4、8 核实验。
IME 实验的核数范围取决于 P0 的实测结果。
不能把每线程预测的最大值称为墙钟耗时的可靠界限。

必须覆盖私有数据、共享只读数据和共享写入数据。
必须检查伪共享、原子操作、屏障、自旋与睡眠等待。
必须检查线程负载不均与任务队列。
必须检查内存带宽竞争和缓存一致性成本。
必须记录线程间的实际依赖边界。
重放的线程交错必须与实际同步约束一致。

采集真实任务的算子形状、调用次数、数据复用与线程分工。
建立任务关键路径。
分别报告算子收益和任务收益。
采集插桩开销时，必须检查插桩对线程到达顺序的影响。
不能从受扰动的同步时间中任意扣除一个固定开销。

## 11. 精度与使用价值

目标是逐步识别 20%、10% 和 5% 量级的收益。
这些数值是待验证的分辨能力目标。
它们不是现有精度声明。
它们也不是候选淘汰门槛。
每个目标必须声明代码族、输入范围和运行条件。

每轮后测必须报告以下指标。

| 指标 | 用途 |
| --- | --- |
| 周期相对误差与尾部误差 | 检查绝对成本估计。 |
| 候选与基线的耗时比值误差 | 检查改进幅度。 |
| 收益误差，单位为百分点 | 检查小收益是否被夸大。 |
| 有可分辨实测变化的方向一致性 | 避免把接近零的符号当作可靠方向。 |
| 配对排序一致性 | 检查投入顺序。 |
| 优先测量前若干候选的实际收益 | 检查有限板端预算的使用价值。 |
| 区间宽度、覆盖与覆盖失败 | 防止宽区间掩盖无用预测。 |
| 适用范围外的识别率与误报 | 检查模型能否识别未知情况。 |
| 每次评估的主机时间与内存 | 检查快速评估是否成立。 |

方向检查必须同时报告实测配对不确定性。
接近零的实测变化必须单独列出。
比较主机成本时，必须给出相同工作量和硬件配置。
必须同时报告轨迹采集成本与模型计算成本。

测量重复性、参数敏感范围与预测误差校准必须分开。
声明的缓存场景范围不是预测置信区间。
校准区间必须说明分组方法和可交换性假设。
少量组的观测覆盖不能确认总体覆盖率。
从多个候选中选择最佳预测时，必须单独检查选择偏差。

## 12. 工具与可复现交付

计划新增或扩展以下组件。

1. CPU 参数资料：每项参数有来源、单位、条件、版本和证据等级。
2. 微基准生成器：产生清单、源码、二进制、反汇编和数值检查。
3. 采集控制器：支持锁、断线恢复、进度记录和安全停止。
4. 轨迹检查器：识别缺失事件、未知指令、状态不完整和截断。
5. 快速状态模型：输出周期、资源等待与敏感度。
6. 后端比较工具：使用同一输入核对功能、误差和计算成本。
