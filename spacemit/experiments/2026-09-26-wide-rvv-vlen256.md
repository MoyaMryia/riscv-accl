# Opt-in 256-bit RVV tiled attention on K1/X60

> Dated campaign snapshot. Measurements apply to the stated workload and date.
> Queued/running statements below are historical; use the
> [current guide](../DOCS.md) and the [experiments index](README.md) for later results and current status.

The previous [wide-head experiment](2026-09-26-wide-rvv-fa.md) used a
SpaceMiT kernel whose dispatcher requires `__riscv_vlenb() == 128`. A
compiled and run 5-line RVV probe on the MUSE-Pi-Pro K1/X60 measured
`vlenb=32` (256-bit vectors). The earlier off/on measurements therefore
never entered that kernel, explaining both the missing activation marker
and the nearly identical TTFT results. The selector was updated to require
the activation marker and skip that inactive candidate.

The new [isolated patch](2026-09-26-wide-rvv-vlen256.patch) keeps the
original 128-byte-vector path intact. For 256-dimensional F16 K/V heads,
it admits the tiled path on 32-byte vectors and uses a per-thread work
buffer. The existing tiled QK dot helper handled one `e16m1` vector of a
64-cell KV tile. On this board, one vector covers only 16 cells; it would
silently leave 48 cells uncomputed if the dispatch guard were simply
changed. Both one-query and four-query dot helpers now loop over all 64
cells in vector-sized segments. Other tiled helpers already loop over
head width or tile width. The one-chunk attention kernel remains excluded
for 256-dimensional heads because it has separate assumptions about the
head fitting in a vector register.

The patch passed board compilation, activation and output gates and was
integrated as described below. It is packaged as optional patch 0009 in
the [deployment helper](../README.md). The
[original short-run script](../reports/raw/2026-09-25-lifecycle/run-lifecycle-rvv32.sh)
and [8k extension](../reports/raw/2026-09-25-lifecycle/run-lifecycle-rvv32-long.sh)
record the historical off/on/on/off protocol. The
[selector](../bench/select-rvv32-long.py) requires complete 32-token outputs,
matching token hashes and enabled-arm activation before admitting a model
to the longer comparison. Those scripts describe the completed campaign.

## Completed board result and integrated build

The isolated build passed activation logging and exact 32-token hash audits
for both models at 128, 2,048, and 8,192 prompt tokens. Two-pass mean 2k
client TTFT fell from 113.78 to 92.45 s for 2B (−18.8%) and from 343.95
to 231.54 s for 4B (−32.7%). At 8k, it fell from 862.62 to 438.05 s
(−49.2%) and 3,194.99 to 1,150.42 s (−64.0%), respectively. Peak RSS
was effectively unchanged. The [completed-gates report](../reports/2026-09-27-completed-gates.md)
contains the matched A/B and limits.

The same patch was applied to the clean integrated board checkout at
`a990751` and `llama-server` rebuilt. An on-path smoke test on both sizes
logged activation and passed an exact-output audit against the isolated
controls. Use `SPINE_FA_WIDE_TILE=1` with the tested Qwen3.5 F16-KV GGUFs.
The flag remains opt-in; the kernel is not a general decode or quantized-KV
acceleration.
