# K1 真实代码片段接入 R2 协议

日期：2026-10-12。
本轮固定模型缺口与小规模配对实测流程。
本轮不拟合模型，也不声明新代码的预测置信度。
R1 的历史样例不能替代本轮实际源码接入。

## 样例与边界

样例取自 `archive/patches-5ad05d8/patches/0007-q8-ime1.patch`。
具体范围是 `make_block_q8_0x16` 的 512 字节载荷重排。
元数据比例复制、张量分配与完整模型执行不在本轮边界内。
基线保留原来的逐列字节重排与清零。
第一候选只移除完整重写前的重复清零。
第二候选移除清零，并按目标顺序执行 8 字节复制。
所有候选继续保留。

独立参考按输出位置反求输入位置。
数值检查包含完整输入、输出与保护区。
输入种子为 `0`、`1` 与 `17`。
种子 `0` 覆盖循环字节序列。
另外两个种子使用确定性伪随机字节。
原生与 QEMU 必须使用同一 ELF。

配置包含 1、16、256 与 4096 个载荷组。
输入与输出总字节数分别为 1024、16384、262144 与 4194304。
指针相对 64 字节对齐基址的偏移分别为 0、1、0 与 1 字节。
这些配置是诊断样例，不是随机总体样本。

构建采用 GCC 16 与 `rv64g`、`lp64d`、`-O3`、静态链接。
本轮是标量夹具，不代表生产向量路径的性能。
必须记录源码、编译器、命令与实际 ELF 身份。
移除重复清零是否被编译器自动完成，必须通过实际二进制检查。

## 最小流程

先固定源码并构建同一夹具。
先执行 QEMU 的全部数值检查。
再对最小配置的三个实现各采集一条完整函数范围轨迹。
写入、多循环或未知指令必须报告为模型缺口。
不能用部分覆盖的指令成本代表整个片段。

只有数值检查通过后，才执行 K1 小规模配对实测。
板端必须空闲。
板端任务必须在 tmux 内全程持有共用锁。
不能在锁冲突时自动重试本批次。

使用 CPU 0、单线程与热输入重复调用。
每个配置先选取三个实现共用的调用次数。
三个实现的试测均达到 10 ms 后，才固定该次数。
试测调用次数上限为 1048576。
达到上限但未满足时长时，本批次明确失败。

正式测量使用三种调用次数与五次重复。
三种调用次数为基础次数的 1、2 与 4 倍。
实现顺序按重复与长度轮换。
两个独立进程各产生 180 条观测。
共用锁覆盖全部数值检查与性能观测。
每个进程的等待上限为 180 s。

记录用户态原始周期事件 `0x22`、墙钟、线程 CPU 时间、频率与调度次数。
事件必须全程运行。
该周期事件的用户态范围沿用现有 K1 审计。
通用指令事件不用于本轮性能结论。
墙钟边界包含片段调用与调用循环开销。
