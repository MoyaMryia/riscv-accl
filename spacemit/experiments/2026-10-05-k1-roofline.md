## Method

- Audit the headers of the two deployed Qwen3.5 Q4_0 GGUFs. Exclude the final
  MTP layer. Include the full tied output head once. Input embeddings are row
  lookups, not a second whole-table read.
- Compile an RVV full-buffer read kernel. Every source word must contribute
  to a checked reduction, which prevents dead-code elimination. Initialize
  and first-touch the portion of each worker on its pinned core. Exclude
  initialization and warm-up from the measurements.
- Buffers: 256, 1,024 and 2,304 MiB. Affinities: core 0, cores 0–1,
  cores 0–3, cores 4–7 and all eight. Five scans per case before and after
  inference. Count read bytes only, and use decimal GB/s.
- Use the validated GEMM-routing library, with modes 0 and 3. Keep wide
  attention enabled, layout 0, four workers, batch/microbatch 32, F16 KV, no
  offloaded layers, no MTP, and no context shifting.
- Two models × two prompt lengths (256/2,048) × two modes × three repeats:
  **24 cold requests**. Each request has exactly 64 output tokens and
  identical prompt tokens in the matched arms. Alternate the mode order.
  Restart the server for each request, and exclude startup from server phase
  throughput.
- Collect separate optimized 2k/one-output-token CPU profiles. These profiles
  are prefill diagnostics. Sampled CPU shares are not removable wall time.
  The runner records a profiler failure, and it does not discard valid timing
  measurements.
- Derive the reference from the median of all ten cores-0–3 scans at the
  predeclared working set: 1 GiB for 2B and 2.25 GiB for 4B. Do not select
  the fastest affinity or launch after you see the results.

## Interpretation

Weight-only reference: bandwidth divided by main weight bytes per step.
Also report a one-pass F16 KV read estimate at the average decode context
length. Neither value estimates actual DDR bytes. Recurrent state,
activations, repeated loads, cache behavior, and compute overhead remain.
The streaming kernel also has instruction overhead. A low
inference/reference ratio does not prove that its difference is removable.

The datasheet 32-bit 2,666 MT/s interface gives 10.664 GB/s raw peak. The
actual memory clock of the board is not established. No throughput-to-TOPS
conversion and no claim of a hardware limit is permitted.

This run is a capped synthetic infrastructure benchmark. It is not
answer-quality validation. No production default changes. Estimated runtime:
30–50 minutes. Board execution budget: four hours after the shared lock.
Lock wait budget: twelve hours. Execution and verified collection both use
tmux.
