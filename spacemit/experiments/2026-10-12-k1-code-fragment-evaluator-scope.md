# K1 优化代码片段性能评估器范围

日期：2026-10-12。
状态：用户已指定收敛目标。
本文件规定后续主线。
[CPU 建模计划](2026-10-12-k1-cpu-model-plan.md)保留为能力路线图。
本次范围调整不改变已封存的模型、界限或证据。

## 1. 目标与使用方式

评估对象是一段待优化代码的基线版本与候选版本。
片段可以是循环、内核的一部分或完整算子。
片段不要求对应独立的算子接口。
两个实现必须完成相同工作。
评估器在其他机器上预测它们在 K1 上的执行成本。
评估器按预计收益与证据缺口安排板端补测顺序。
全部候选均保留。
评估器不设置性能淘汰门槛。

片段可以包含多个循环、分支、加载、写入与状态更新。
现有固定循环模型作为片段评估器的机制底座。
本次缩小范围不能直接提高旧模型的预测精度。

### 1.1 优化前的低成本评估

核心目标是减少缺少证据的大规模全量测试。
评估器必须帮助开发者确定下一步工作。
首先记录基线瓶颈、拟改变的机制与预计受益条件。
尚未实现的方案可以先检查成本上限与关键假设。
此时的结果属于假设分析，不能称为已验证的代码预测。

已有候选按以下顺序获取证据。

| 步骤 | 最小工作 | 用途 |
| --- | --- | --- |
| 正确性检查 | 核对片段边界、编译结果与代表输入的数值输出。 | 确认比较对象完成相同工作。 |
| 主机快速评估 | 预测代表输入下的成本差，并检查模型缺口与参数敏感度。 | 找出值得投入的改法与可能使判断反转的条件。 |
| K1 小规模配对实测 | 只测能区分当前假设的输入或实现。 | 补充最可能改变投入顺序的证据。 |
| 扩大验证 | 根据前面证据选择形状、运行条件与集成检查。 | 核对收益范围与实际调用位置的影响。 |

模型缺少覆盖时，可以直接安排小规模实测。
不能通过未知路径的虚构预测安排投入顺序。
高不确定性与预计收益小都不表示淘汰候选。
建议必须说明当前依据、下一项行动与所需成本。
全量测试不作为每次修改后的默认动作。
全量测试也不由单项预测阈值自动触发。

每批检查必须预先声明输入数量与机器时间预算。
必须记录构建、轨迹采集、模型计算与板端实测的总成本。
不能只用模型计算时间代表评估器使用成本。
若最小补测能回答当前问题，不扩成全形状或全模型测试。
证据不足时，输出待补测条件。

评估器验收必须包含测试成本的对照。
在预先保留的优化任务中，比较全量测试与分阶段评估所用的时间。
同时报告排序价值、错误方向与被延后候选中的实测收益。
不能只报告节省的测试时间而隐藏漏报的优化机会。

## 2. 首版边界

首版使用指定 K1、CPU 0、单线程和固定构建配置。
每项结果必须记录实际二进制、输入、精度、循环长度、步长与数据布局。
必须记录入口处的有效寄存器值与片段使用的内存状态。
必须记录出口处仍被后续代码使用的值与内存副作用。
每项结果必须声明缓存条件与测量边界。
首版先使用热输入重复执行。
热输入不保证全部访存命中一级缓存。
训练范围必须包含不同工作集尺寸。
范围外查询必须报告证据缺口。

基线与候选必须使用相同的测量边界。
边界内的布局转换、打包、临时区处理与状态回写必须计入。
已有预打包输入的查询必须显式声明此前提。
边界外的准备成本必须单独声明。
不能把片段收益称为完整算子或任务收益。
分配、初始化与函数调用是否计入，必须在协议中固定。

必须核对实际编译上下文。
把片段提取为函数可能改变内联、寄存器分配、溢出与指令布局。
夹具必须保留待测片段，防止编译器删除或移出循环。
若提取改变关键机器码，必须另行核验原位置的性能。
独立夹具的预测不能自动转用于原调用位置。
入口处尚未完成的访存与跨边界依赖必须显式处理。
首版不覆盖的入口状态必须报告为缺口。

首批复用已验证的标量重排片段与现有算子夹具中的明确片段。
IME M4 内核与 SSM 卷积提供后续接入样例。
IME 指 K1 的整数矩阵扩展。
SSM 指状态空间模型。
IME M4 仍是内核范围，不能代表完整矩阵乘法。
若选择完整矩阵乘法作为片段，边界必须包含其实际打包与分块路径。
新片段族逐个接入。
未验证的指令路径不能通过累加旧成本生成已校准预测。

多线程片段作为后续独立范围。
已有四线程数据继续保留。
跨算子融合、任务关键路径与完整模型耗时暂缓。
多核同步与经 K1 标定的详细模拟器暂缓。
这些能力不是首版片段评估器的完成条件。

## 3. 输入与输出契约

输入必须包含以下内容。

1. 片段语义、源码边界、基线与候选身份。
2. 源码、实际二进制、编译参数和依赖库身份。
3. 输入数据类型、循环长度、步长、布局与数据生成规则。
4. 出口有效值、数值误差规则、状态更新规则与别名约束。
5. 核编号、线程数、工作集与缓存准备方式。
6. 打包、分配、初始化和测量的边界。

输出必须分开报告以下内容。

| 输出 | 含义 |
| --- | --- |
| 基线与候选成本 | 声明范围内的周期或耗时。不能混合不同边界。 |
| 候选/基线比值 | 相同输入、相同工作量与相同条件下的成本比例。 |
| 每次节省耗时 | 每次执行片段的预测差值。它不是完整任务收益。 |
| 数值状态 | 已验证、失败或待验证，并附核验配置。 |
| 误差证据 | 独立后测的误差、方向、排序与失败样例。 |
| 适用范围 | 已校准代码族、形状、工作集、指令路径与缓存条件。 |
| 下一项补测 | 能改变候选投入顺序的未知条件与对应实验。 |

重复测量范围只描述观测波动。
假设场景范围只描述所选假设。
预测误差界限必须通过独立校准获得。
预测界限必须声明分组方式与可交换性假设。
旧形状模型与固定循环模型的界限不能转用于新片段实现。

## 4. 实施顺序

| 顺序 | 工作 | 完成证据 |
| --- | --- | --- |
| 1 | 固定代码片段契约与首批清单。 | 每个样例有入口与出口边界、数值参考、构建身份和缓存协议。 |
| 2 | 接入实际片段二进制与轨迹。 | 所有执行路径有覆盖记录；未知路径显式报告缺口。 |
| 3 | 补充实际片段所需的机制标定。 | 优先检查 R8 漏报所涉循环边界，再检查工作集与写入成本。 |
| 4 | 按代码改进族隔离训练、校准与后测。 | 同一改进族的形状变体不能分散到训练与独立后测。 |
| 5 | 在未见实现上检查成本与收益。 | 同时报绝对误差、尾部误差、收益百分点误差、方向、排序和漏报。 |
| 6 | 发布便携代码片段评估入口。 | 本机与 server 重放一致；输出保留全部候选、范围与补测建议。 |

各阶段使用新的批次身份。
必须在观测后测性能前冻结模型与校准界限。
数值失败的样例不能产生有效收益结论。
数值失败的样例仍保留在记录中。
历史后测数据可以用于诊断。
历史后测数据不能再次称为独立后测。

先检查 20%、10% 与 5% 量级的收益分辨能力。
这些量级是待验证目标。
它们不是当前精度声明，也不是候选淘汰门槛。
完整完成条件是声明范围内的独立片段检查与可重放交付。
不能仅用固定循环覆盖率宣布代码片段评估器完成。

## 5. 当前能力与缺口

已实现：固定算子形状查询、原生采集、数值核验、证据归档与便携重放。
已验证：[形状模型 V1](../reports/2026-10-12-k1-operator-model-v1.md)的固定实现对。
V1 的 IME 后测方向一致为 18/18。
V1 的卷积后测方向一致为 16/18。
这些结果包含单线程与四线程配置。
它们不能证明首版新实现的独立精度。

已实现：实际固定循环的状态模型与二进制接入。
已验证：[R8](../reports/2026-10-12-k1-cpu-completion-model-r8.md)的固定标量热只读循环。
R8 的独立数值等价重排方向一致为 10/12。
R8 漏报两个约 8.16% 的实测收益。
这些失败继续保留为诊断入口。

未实现：任意代码片段新实现的完整接入与可信预测。
待标定：片段实际使用的访存、写入与控制流条件。
待验证：保留代码改进族的收益精度与排序价值。
待实现：统一的代码片段输入契约与便携查询入口。
