# K1 真实算子数据采集

## 已实现

本工具先固定形状分组，再采集训练部分。
`plan.json` 是首批计划。
每类算子有 8 个训练形状、19 个校准形状和 9 个后测形状。
同一形状的单线程与四线程配置属于同一分组。
本批次共有 32 个训练配置。

IME 指 K1 的整数矩阵扩展。
IME 数据调用已验证库中的实际 M4 内核。
每个线程使用相同的 A 输入与不同的 B 输入。
四线程配置增加总输出列数。
这项配置测量固定单线程工作量下的扩展表现。
其范围不包含生产矩阵乘法的打包、分块调度与后端同步。

SSM 指状态空间模型。
卷积数据使用实际 SSM 卷积计算图。
其范围包含拼接、布局转换、卷积与状态回写。
两个版本共用一个线程池。
单线程与四线程配置使用相同的总工作量。

每个配置先运行两个版本的数值检查。
程序保留输入、输出、状态与保护区的完整转储。
独立参考、保护区与输入不变检查必须通过。
两个版本的完整转储必须相同。
数值失败会停止本批次。

性能采集使用热输入重复执行。
每个配置使用 7 次重复与 3 个执行长度。
同一次重复中的两个版本使用相同执行次数。
程序交替测量两个版本。
当前程序先测量两个版本，各测量 2 次。
程序增加公共执行次数，直到这 4 个试测都达到 10 ms。
正式观测仍保留实际耗时。
程序不删除低于目标时长的正式观测。
程序保留全部性能观测。
本工具不设置性能淘汰门槛。

IME 数据包含每个工作线程的原始周期事件 `0x22`。
程序同时记录通用指令事件、线程 CPU 时间、频率与调度次数。
程序要求性能计数器全程运行。
原始周期事件的用户态过滤依据既有 K1 审计。
通用指令事件的用户态过滤仍待独立验证。
卷积数据只把整个计算图的墙钟耗时作为性能目标。

## 执行

必须先检查机器任务与共用锁。
必须在新的批次目录中执行。
必须在 tmux 中运行 `run-board.sh`。
该脚本全程持有共用锁。
不得重复执行已有批次。

```sh
python3 plan.py /path/to/new-plan.json
```

`collect.py` 复用板端已验证的库与数值夹具。
工具把运行依赖复制到批次目录。
工具记录夹具修改、构建参数、源文件、库与二进制的散列。
`frozen-artifacts.json` 在性能采集前固定这些文件。
`sha256.json` 在采集完成后固定证据文件。

完成后，在有 Python 3.10 或更新版本的机器上执行以下命令。

```sh
python3 summarize.py /path/to/batch /path/to/summary.json
```

汇总程序核验文件散列、分组身份、配对次数与计数器覆盖。
汇总结果保留每次重复的执行长度斜率与截距。
配对差值的最小值与最大值描述本批次观测范围。
这些范围不是预测置信区间。
