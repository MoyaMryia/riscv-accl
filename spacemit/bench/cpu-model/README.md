## 当前入口

当前主线收敛为[优化代码片段性能评估器](../../experiments/2026-10-12-k1-code-fragment-evaluator-scope.md)。
目标是用低成本证据安排优化投入与补测顺序。
先检查正确性，再做主机预测，必要时补充 K1 小规模配对实测。
大规模全量测试不作为每次修改后的默认动作。
首版固定为单线程与声明的热输入条件。
片段边界内的打包、布局转换与状态回写必须计入成本。
现有固定循环模型作为机制底座。
新片段实现的独立预测精度仍待验证。
多核任务模型与详细模拟后端暂缓。

有限片段比较入口见[使用说明](FRAGMENT-COMPARE.md)。
`fragment-compare.py` 核验两臂 ELF、完整轨迹与所附数值参考。
它并列输出冻结模型的点预测，并保留模型分歧与零收益候选。
它不自动触发全量测试。
新片段的独立预测精度仍待验证。

真实源码接入见[源码夹具说明](FRAGMENT-SOURCE.md)。
[R2 报告](../../reports/2026-10-12-k1-fragment-source-r2.md)记录 Q8 载荷片段的数值与原生配对结果。

[R3 报告](../../reports/2026-10-12-k1-fragment-call-r3.md)记录范围外清零函数的 RVV 路径与 K1 目标核验。

连续复制的方向随配置变化。
这些实测没有补齐真实函数的快速预测模型。
新增[有限调用点估计](FRAGMENT-TIMING.md)接入共同调用循环、标量写入与部分向量清零。

真实新优化片段的预测精度仍未验证。

最新标量候选见[第八轮报告](../../reports/2026-10-12-k1-cpu-completion-model-r8.md)。

该界限不转用于重排或新算法。

这项对照不是独立后测。

通用 CPU 评估器仍未完成。
第六轮 9/9 组覆盖伴随 1.6495 的校准因子。
收益误差最大仍为 30.3592 个百分点。

新二进制输入使用 `binary-input.py`。

## 已实现与已验证

已实现：微基准生成、实际机器码核对、数值参考、板端采集和每核扩展核验。
已实现：顺序发射、寄存器就绪、操作数读占用与执行资源状态。
已实现：仅用训练性能拟合、冻结模型、独立校准与后测。
已实现：标准 Python 便携重放和完整归档发布。

已验证：CPU 0 上 104 个固定循环。
已验证：208 份原生完整转储与同一 ELF 的厂商 QEMU 转储一致。
已验证：5,616 条有效周期样本。
已验证：冻结界限覆盖最终 9 个组中的 7 个。
方向符号一致为 8/9。
该结果尚不能证明任意新算法的判断能力。

第二轮已验证：286 个固定循环、12,012 条样本和 572 份原生转储。
172 对重排版本的完整转储一致。
第二轮后测方向一致为 18/18，组覆盖仍为 7/9。
全部版本的收益误差中位数为 12.4224 个百分点。
该结果仍不能提供任意新算法的高置信度判断。

模型参数是有效时序。
这些参数不能直接解释为真实端口数、真实加载延迟或真实流水级数。
训练中仍存在参数不可区分的情况。

第三轮已验证：306 个固定循环、9,180 条样本和 612 份原生转储。
后测方向一致为 26/26，但全部候选均实测变慢。
13/13 组覆盖伴随 1.9918 的校准因子。
收益误差中位数为 7.9417 个百分点。
41 个训练等效变体仍在新组合上产生不同预测。

第四轮已验证：18 组固定标量重排均实测变快。
方向一致为 18/18，收益误差中位数为 1.7389 个百分点。
机制探针同时保留最大 2.5000 的周期误差因子。
范围见[第四轮报告](../../reports/2026-10-12-k1-cpu-mechanism-probes-r4.md)。

第五轮已验证：168 个新函数与 336 份完整转储。
拆分重复写入间隔后，三链探针的最大误差扩大到 2.7143 倍。
本轮模型不能替换第三轮模型。
48 对源操作数交换均未出现超过 1% 的实测变化。
结果见[第五轮失败报告](../../reports/2026-10-12-k1-cpu-write-model-r5.md)。

第六轮已验证：118 个函数、3,540 条样本与 236 份完整转储。
12 个可分辨的后测版本均变慢，方向一致为 12/12。
另外 6 个版本接近不变。
新模型的中位收益误差退步与最大收益误差改善同时保留。
历史正收益回归方向为 35/36，漏报继续保留。

## 实验语义

第一轮两臂分别采用交错顺序与按操作类型分组的顺序。
操作集合相同不保证程序语义相同。
部分标量组合会改变结果。
每个程序分别对照自身的数值参考。
两臂没有通用的数值等价声明。
第一轮比值用于检查 CPU 成本预测。
不能把这些比值直接称为可采用的算法优化收益。

第二轮的重排保留寄存器依赖顺序。
两个顺序版本还通过完整输出比较。
该语义约束只覆盖本次固定只读输入程序。

## 后续能力

完整调用的新拟合必须使用 `fragment-fit-checked.py`。
该入口核验全部轨迹，并从原生证据重新提取训练视图。
`fragment-toolchain.py` 固定完整本地工具依赖。
`fragment-bind.py` 从封存包核验历史核心，再发布参数不变的绑定模型。
新模型与历史绑定模型均拒绝依赖模块漂移。
用法见[有限调用入口](FRAGMENT-TIMING.md)。

已实现：六类固定计数循环的实际二进制与动态轨迹适配。
待实现：其他指令、控制流、访存状态和调用边界的完整适配。
待验证：受控程序范围之外的代码重排、新算法与更广的输入数据。
待标定：缓存缺失、分支恢复、地址转换和多核同步。
未实现：经过 K1 标定的详细模拟后端。
这些缺口按代码片段范围选择实施顺序。
完整 CPU 路线图继续保留。
