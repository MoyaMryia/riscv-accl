# 优化片段完整调用轨迹

本入口记录首次目标调用到返回地址之前的全部指令。
它包含地址范围之外的被调用函数。
它用于补齐完整调用模型的输入。
它不自动启动原生测试或全量测试。

## 使用方法

先完成[源码夹具数值检查](FRAGMENT-SOURCE.md)。
使用相同 ELF 与相同 QEMU。
明确选择需要采集的配置。

```sh
python3 -B spacemit/bench/cpu-model/fragment-call.py \
  --payload /path/to/payload --qemu-check /path/to/qemu-check \
  --qemu /path/to/qemu-riscv64 --header /path/to/qemu-plugin.h \
  --output /path/to/new-call-check --cases 0 1
```

程序在主机上构建独立的 QEMU 插件。
构建需要 C 编译器、GLib 与 QEMU 插件头文件。
输出目录必须此前不存在。
默认轨迹上限为 200000 条指令。
`--max-instructions` 可以设置新的明确上限。
达到上限的调用不能通过核验。

## 调用边界

插件在目标函数入口读取 `ra` 返回地址。
插件在处理器再次到达该地址前停止记录。
该地址的调用方指令不属于片段轨迹。
程序只接受一个处理器的完整调用轨迹。
没有完整返回、记录截断或结束计数不同均使核验失败。

每条指令必须与原 ELF 的可执行节相同。
直接跳转与条件分支必须符合指令编码。
连续执行路径不能有未解释的空档。
调用栈核验覆盖 `x1` 与 `x5` 的标准调用和返回形式。
其他调用约定、异常展开与非局部返回仍未覆盖。
间接跳转目标来自轨迹，没有独立重放全部寄存器值。

## 指令与访存

解码器只接入明确列出的 RV64 整数与压缩指令。
未知指令不会转换为默认算术成本。
完整调用包含未接入指令时，当前入口停止并保留失败目录。

向量路径只接入 `vsetvli`、未掩码移动与 `vse8.v`。
移动与写入必须使用 e8、整数 LMUL 与 `vstart=0`。
寄存器依赖包含全部 LMUL 寄存器组。
`vse8.v` 的访存长度来自实际 `vl`。
全部访存回调必须满足长度、连续性、方向与不重叠规则。

输出保留函数范围外指令数、控制路径、访存字节数与向量状态。
解码轨迹保留寄存器读写关系与访存地址。
访存字节数包含栈和库函数的访问。
虚拟访存字节数不是实测缓存流量。

## 当前能力与限制

Q8 样例的六次完整调用已通过核验。
基线的清零路径使用 RVV，见[完整调用 R3 报告](../../reports/2026-10-12-k1-fragment-call-r3.md)。
原基线函数范围轨迹未包含该路径。
K1 调试探针确认相同 ELF 选择相同清零函数目标。
该探针不证明完整原生指令序列与 QEMU 相同。

本入口仍不输出 K1 完整调用周期或预测置信度。
新增[有限调用点估计](FRAGMENT-TIMING.md)使用共同调用循环轨迹计算周期斜率。
该估计仍没有新片段预测置信区间。
首次调用轨迹不能证明热重复调用的路径和向量状态相同。
写入成本、调用边界、多循环与工作集模型仍待标定。
完整调用核验不证明新代码片段的预测精度。

## 指令语义来源

压缩指令以 [RISC-V C 2.0 规范](https://docs.riscv.org/reference/isa/v20260120/unpriv/c-st-ext.html)为核对来源。
向量状态以 [RISC-V V 1.0 规范](https://docs.riscv.org/reference/isa/v20260120/unpriv/v-st-ext.html)为核对来源。
本工具只实现上述说明中的子集。
