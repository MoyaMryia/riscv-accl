# 优化代码片段比较入口

范围见[片段评估计划](../../experiments/2026-10-12-k1-code-fragment-evaluator-scope.md)。
`fragment-compare.py` 提供第一版有限比较入口。
它比较基线与候选的实际机器码。
它不接受仅凭指令数量生成的收益结论。
它也不表示通用片段评估器已经完成。

## 已实现范围

输入是一个固定计数循环的两个版本。
每次迭代必须完成相同工作。
已覆盖的循环体指令为 `add`、`mul` 与只读 `load`。
循环计数使用减一与后向条件分支。
目标配置为 K1 CPU 0 与单线程。
加载必须声明热只读场景。

工具核验 ELF、轨迹、数值转储与模型的 SHA-256 身份。
工具从实际 ELF 解码寄存器依赖。
工具核验完整动态循环路径与加载回调。
工具比较所附基线、候选与参考输出的完整字节。
转储的实际完整范围与生成过程由测试夹具协议提供。
有限输入的字节一致不能证明所有输入语义等价。

工具可以并列使用第三轮、第六轮与第八轮的冻结模型。
第三轮模型的文件格式版本仍为 `schema=2`。
引擎身份必须与各模型内的 `engine_files` 一致。
工具不把模型分歧范围称为预测界限。
模型全部一致也不证明预测准确。
模型预测相同成本时，候选仍被保留。

预测目标是包含计数回边的稳态每迭代周期。
预测不包含初始化、函数首尾、调用、循环启动与排空。
首版不预测缓存缺失、写入、其他分支或任意入口状态。
首版不预测更改每迭代工作量的循环展开方案。
这些输入必须补充适配或先做小规模实测。

## 输入清单

路径相对于清单文件所在目录。
`baseline` 与 `candidate` 分别声明 ELF、函数符号、轨迹与轨迹迭代次数。
每个文件证据对象使用 `path` 与 `sha256`。
完整可运行清单位于便携包的 `manifests/` 目录。

| 字段 | 要求 |
| --- | --- |
| `schema`、`id` | 文件格式版本为 `1`，并提供片段对身份。 |
| `contract` | 声明相同工作、入口有效值、出口有效值、内存副作用与编译上下文。 |
| `baseline`、`candidate` | 包含 `elf`、`symbol`、`trace` 与 `iterations`。 |
| `models` | 每项包含唯一 `id`、冻结 `model` 与配套 `engine`。 |
| `primary_model` | 指定主模型身份，同时保留其他模型结果。 |
| `numerical_checks` | 每项提供基线、候选与参考转储；绑定两臂 ELF 身份。 |
| `cost_seconds` | 声明构建、轨迹采集与原生测量成本；未知值使用 `null`。 |

契约必须包含以下字段。

```json
{
  "work_id": "same-work",
  "input_description": "固定整数输入与循环长度。",
  "boundary": "循环体、计数减一与回边。",
  "compile_context": "原位置或已核验的提取位置。",
  "live_inputs": ["入口寄存器与输入缓冲区。"],
  "live_outputs": ["出口有效值。"],
  "memory_effects": ["只读输入；循环之外保存结果。"],
  "equivalent_work_per_iteration": true,
  "cpu": 0,
  "threads": 1,
  "boundary_kind": "steady-loop",
  "memory_scenario": "hot-read-only",
  "entry_state": "repeated-steady-loop"
}
```

这些字段是调用者声明。
工具不能通过声明证明实际缓存状态或完整语义。
更改编译上下文后，必须核对原位置的机器码与性能条件。

## 执行与结果

输出文件必须此前不存在。

```sh
python3 -B spacemit/bench/cpu-model/fragment-compare.py pair.json \
  --output comparison.json --markdown comparison.md
```

数值输出不同会产生 `numerical-failed`。
文件身份、动态路径或契约缺口会产生 `evidence-incomplete`。
完整范围内的点预测产生 `exploratory-pair-estimate`。
所有状态均保留候选。
数值失败不产生有效收益预测。

结果包含两臂周期、耗时比例、预测收益与模型分歧。
结果包含下一项低成本工作建议。
结果不附加新片段的预测置信度或预测界限。
结果不自动启动板端测量或全量测试。

工具记录本次核验与模型计算的耗时。
外部构建、轨迹与原生测量成本分别记录。
未知成本不会被记为零。
总成本尚未核验时，`total_seconds` 保持 `null`。

## 便携历史回归

解压便携包后，在包目录执行以下命令。

```sh
python3 -B run-fragment-examples.py --output /path/to/new-replay.json
```

工具核验包内收据并重放四对片段。
两个历史漏报必须继续保留。
本检查验证接入关系与错误结论防护。
它不能替代未见代码改进族的独立后测。
