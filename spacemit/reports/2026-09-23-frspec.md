# Frequency-ranked 32k MTP draft head on SpaceMiT X60

Date: 2026-09-23. This is an isolated prototype on `codex/frspec-d2t`, based on the official `port-gdn` fork at `6562c22`. The original checkout and build were not modified. The only source change is `llama.cpp/src/models/qwen35.cpp`: load an optional I64 `d2t` GGUF tensor and scatter compact draft logits to their full-vocabulary token IDs. Without `d2t`, the existing prefix-head path remains.

## Method

- Model: Qwen3.5-2B MTP, Q4_0 draft head, on `musepipro-wg`.
- Three variants: mapped 32,768 rows, existing 32,768 prefix rows, existing 65,536 prefix rows. All 335 shared non-head tensors have identical SHA-256 hashes; only the draft head differs, and the mapped model adds `d2t`.
- Training map: count tokens in 809,481 tokens from public `llama.cpp/docs`, `tools` source, and Chinese `llm-bench` Markdown. Rank observed IDs by frequency; include IDs 248000-248319; fill unused rows by ascending ID. The saved map hash is `19e1f1ca60967da53d1d5c278232960f0ff72ccf8c71d76888a9837f164a23f9`.
- Held-out `llama.cpp/src` and `common` source: 1,421,054 tokens. Token coverage: prefix32 92.853%, prefix64 97.592%, mapped32 98.619%. Coverage is not acceptance or throughput.
- Server: 4 threads, context 8192, parallel 1, batch/microbatch 32, flash attention on, `SPINE_SPEC_RS=1`, MTP draft max 3, `temperature=0`, seed 42, `cache_prompt=false`, 128 generated tokens. Two passes, with reversed model and prompt order in pass 2. Values below are mean decode tokens/s across those two passes.

| Prompt | Mapped 32k | Prefix 64k | Prefix 32k | Mapped vs 64k |
| --- | ---: | ---: | ---: | ---: |
| English: relativity | 6.797 | 6.518 | 6.077 | +4.3% |
| Python Fibonacci code | 5.877 | 5.691 | 5.840 | +3.3% |
| Chinese RISC-V explanation | 4.924 | 3.579 | 3.659 | +37.6% |

All variants generated exactly the same 128-token greedy text for each prompt in both passes. In pass 1, mapped draft acceptance was 83/130, 76/153, 66/183; prefix64 was 82/131, 76/153, 45/243; prefix32 was 77/148, 75/156, 43/249, respectively. The Chinese improvement comes from materially better draft acceptance.

Direct decoding of the same mapped GGUF without MTP was about 5.10 tokens/s on all three prompts in one pass. Thus MTP max 3 is faster for these English/code prompts, while direct decoding is about 3.5% faster for this Chinese prompt. Mapped MTP max 2 gave 5.229/4.839/4.013 tokens/s; max 4 gave 5.777/4.908/3.865. Max 3 is the best of the tested draft lengths.

## Recommendation

Keep the mapped 32k head as an experimental option. Extend the comparison to representative long-context, multilingual, and code workloads before making it the default. Retain a direct-decoding fallback for low-acceptance prompts. The map is corpus-dependent; these three prompts and two passes do not establish general workload gains. No commit, push, or PR was made.
