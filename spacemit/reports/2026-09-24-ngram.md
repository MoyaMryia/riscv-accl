# N-gram first, MTP fallback on MUSE-Pi-Pro

> Dated campaign snapshot. The measurements apply to the stated workload and
> date. Queued/running statements below are historical. Use the
> [current guide](../DOCS.md) and the [reports index](README.md) for later
> results and for the current status.

Date: 2026-09-24. Board: SpaceMiT X60. This experiment is a no-source-change
configuration test on the official `spacemit-llama` fork. The initial
decomposition used also the 2B mapped-head prototype.

## Finding

`--spec-type ngram-mod,draft-mtp` tries n-gram drafting first. It falls back
to MTP when it cannot draft. For copy-heavy code editing, this mode
outperformed either drafter alone. A requirement of a full 16-token n-gram
match removed the slowdown that shorter and weaker matches caused on a
Python edit.

Recommended candidate flags for the tested single-stream configuration:

```bash
SPINE_SPEC_RS=1 ./build/bin/llama-server \
  -m models/Qwen3.5-2B-MTP-Q4_0-embQ4_0-dv64k.gguf \
  -t 4 -c 8192 --parallel 1 -b 32 -ub 32 -fa on \
  --spec-type ngram-mod,draft-mtp \
  --spec-ngram-mod-n-match 16 \
  --spec-ngram-mod-n-min 16 \
  --spec-ngram-mod-n-max 16 \
  --spec-draft-n-max 3
```

The established `spine-tcm`, `spert`, and build library paths must stay in
`LD_LIBRARY_PATH`, as in `~/Projects/llm-bench/FINAL-REPORT.md`.

## Measurement

All requests used `temperature=0`, seed 42, `cache_prompt=false`, one slot,
and 4 threads. The C++ prompt supplied the `common/ngram-mod.cpp` functions
and asked for a one-constant change, with the full source returned. The
Python prompt supplied a short function and asked for a loop-variable
rename. The prose prompt asked about RISC-V vector matrix multiplication.
All 2B responses reached the 160-token limit and produced identical output
hashes across modes. Decode tokens/s:

| 2B, official fork and existing 64k head | C++ near-copy | Python rename | Prose |
| --- | ---: | ---: | ---: |
| MTP only, n-max 3 | 7.994 | 6.898 | 5.156 |
| N-gram first, min 4/max 16 | 10.252 | 6.453 | 5.153 |
| N-gram first, min 8/max 16 | 10.377 | 6.530 | 5.216 |
| **N-gram first, min 16/max 16** | **10.364, 10.368** | **6.967, 6.987** | **5.215, 5.222** |

The tuned mode is about **29.7% faster in decode** than MTP only on the C++
near-copy. The other two differences are about 1%. Treat those two as ties
at this sample size. In the first exploratory run on the isolated
mapped-head build, the plain, n-gram only, mapped MTP, and combined (min 4)
modes gave 4.903 / 8.598 / 8.203 / 10.386 tokens/s on the same C++ edit.
N-gram alone accepted 110 of 116 draft tokens there.

For 4B with the existing 64k head, the same C++ task generated 128 tokens
with identical output: MTP only 3.390 tokens/s, and the tuned combined mode
3.634 (+7.2%). The 4B Python prompt stopped after one token in both modes,
so it is not a useful speed comparison.

## Scope

The strongest result is a near-copy task with substantial source in the
prompt. It does not establish a general code-generation or chat gain. The 2B
combined setting ran twice in opposite prompt order. The MTP-only and 4B
measurements were single passes. A larger workload with representative
edits, longer contexts, and concurrency is necessary before a change to the
general server default. `SPINE_SPEC_RS=1` is for dedicated single-stream
use. Evaluate the existing high-concurrency checkpoint/gate configuration
separately.

Upstream documents the n-gram and combined speculative modes at
https://github.com/ggml-org/llama.cpp/blob/master/docs/speculative.md.
We made no commit, push, or PR.
