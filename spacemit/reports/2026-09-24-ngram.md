# N-gram first, MTP fallback on MUSE-Pi-Pro

Date: 2026-09-24. Board: SpaceMiT X60. This is a no-source-change configuration experiment on the official `spacemit-llama` fork; the 2B mapped-head prototype was also used for the initial decomposition.

## Finding

`--spec-type ngram-mod,draft-mtp` tries n-gram drafting first and falls back to MTP when it cannot draft. For copy-heavy code editing, it outperformed either drafter alone. Requiring a full 16-token n-gram match removed the slowdown seen with shorter, weak matches on a Python edit.

Recommended candidate flags for the tested single-stream configuration:

```bash
SPINE_SPEC_RS=1 ./build/bin/llama-server \
  -m models/Qwen3.5-2B-MTP-Q4_0-embQ4_0-dv64k.gguf \
  -t 4 -c 8192 --parallel 1 -b 32 -ub 32 -fa on \
  --spec-type ngram-mod,draft-mtp \
  --spec-ngram-mod-n-match 16 \
  --spec-ngram-mod-n-min 16 \
  --spec-ngram-mod-n-max 16 \
  --spec-draft-n-max 3
```

The established `spine-tcm`, `spert`, and build library paths must still be present in `LD_LIBRARY_PATH` as in `~/Projects/llm-bench/FINAL-REPORT.md`.

## Measurement

All requests used `temperature=0`, seed 42, `cache_prompt=false`, one slot, and 4 threads. The C++ prompt supplied the `common/ngram-mod.cpp` functions and asked for a one-constant change while returning the full source. The Python prompt supplied a short function and requested a loop-variable rename. The prose prompt asked about RISC-V vector matrix multiplication. All 2B responses reached the 160-token limit and produced identical output hashes across modes. Decode tokens/s:

| 2B, official fork and existing 64k head | C++ near-copy | Python rename | Prose |
| --- | ---: | ---: | ---: |
| MTP only, n-max 3 | 7.994 | 6.898 | 5.156 |
| N-gram first, min 4/max 16 | 10.252 | 6.453 | 5.153 |
| N-gram first, min 8/max 16 | 10.377 | 6.530 | 5.216 |
| **N-gram first, min 16/max 16** | **10.364, 10.368** | **6.967, 6.987** | **5.215, 5.222** |

The tuned mode is about **29.7% faster in decode** than MTP only on the C++ near-copy. The other two differences are about 1% and should be treated as ties at this sample size. In the first exploratory run on the isolated mapped-head build, plain / n-gram only / mapped MTP / combined (min 4) were 4.903 / 8.598 / 8.203 / 10.386 tokens/s on the same C++ edit. N-gram alone accepted 110 of 116 draft tokens there.

For 4B with the existing 64k head, the same C++ task generated 128 tokens with identical output: MTP only 3.390 tokens/s; tuned combined mode 3.634 (+7.2%). The 4B Python prompt stopped after one token in both modes and is not a useful speed comparison.

## Scope

The strongest result is a near-copy task with substantial source in the prompt. It does not establish a general code-generation or chat gain. The 2B combined setting was run twice in opposite prompt order; the MTP-only and 4B measurements were single passes. A larger workload with representative edits, longer contexts, and concurrency is needed before changing the general server default. `SPINE_SPEC_RS=1` is for dedicated single-stream use; the existing high-concurrency checkpoint/gate configuration should be evaluated separately.

Upstream documents the n-gram and combined speculative modes at https://github.com/ggml-org/llama.cpp/blob/master/docs/speculative.md. No commit, push, or PR was made.
