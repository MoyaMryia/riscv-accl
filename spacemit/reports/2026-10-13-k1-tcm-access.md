# K1 的 TCM 访问权限检查

日期：2026-10-13。
设备为 `moyamryia-spacemitk1xmusepiproboard`。
内核为 `6.6.63 #2.2.9.2`。
本轮使用 sudo 核对普通用户的访问失败原因。
本轮没有修改设备权限、驱动或系统配置。

## 已验证：普通用户受设备权限限制

TCM 指紧耦合存储器。
`/dev/tcm` 为字符设备，主设备号为 10，次设备号为 122。
设备属主和属组为 `root:root`，权限为 `0600`。
当前普通用户 `moyamryia` 的 UID 为 1000。
该用户没有设备读写权限。
系统没有匹配 TCM 的 udev 访问规则。

[普通用户直接访问](raw/k1-tcm-access-20261013/user-map-read.json)返回 `errno=13`，即权限不足。
此前运行时的 `available=0` 结论只适用于该普通用户进程。
该结论不能解释为设备没有 TCM。

## 已验证：sudo 可以访问真实 TCM

内核配置为 `CONFIG_SPACEMIT_TCM=y`。
TCM 驱动编入内核，因此不需要另行加载 TCM 模块。
`/sys/class/misc/tcm` 与 `/dev/tcm` 均存在。

以 sudo 执行同一 `libspine_tcm.so.3.0.1` 检查后，运行时返回 `available=1` 与 `fake=false`。
运行时报告 4 个块，每块 131072 bytes，即 128 KiB。
[sudo 运行时记录](raw/k1-tcm-access-20261013/root-runtime-audit.json)保留设备身份与完整返回值。

在项目共用锁下执行四块只读映射检查。
每块的映射、首字节读取与末字节读取均通过。
本轮没有写入 TCM 内容。
[sudo 映射记录](raw/k1-tcm-access-20261013/root-map-read.json)保留逐块结果。
这些检查证明当前权限差异会影响 TCM 访问。
这些检查不提供内存带宽或模型加速结论。

## 同步内存接口仍然缺失

`/dev/tcm_sync_mem` 不存在。
当前内核的 misc 设备列表没有对应设备。
sudo 不能使不存在的接口变为可用。

固定源码中的 `spine_mem_pool_shared_mem::alloc_chunk` 单独打开 `/dev/tcm_sync_mem`。
该路径失败后，初始化屏障回退到堆内存。
`/dev/tcm` 的权限问题与该接口缺失是两项独立问题。
不能只改 `/dev/tcm` 权限就宣称同步回退已经消失。

## 状态与后续测量条件

已验证：当前普通用户的 TCM 访问失败由权限限制引起。
已验证：sudo 进程可以识别并只读映射四块真实 TCM。
未实现：普通用户的持久访问规则。
待验证：当前运行时与内核同步内存接口的配套关系。
待验证：启用真实 TCM 后的模型性能与完整输出一致性。

后续基线与候选必须使用相同用户、设备权限与运行时。
不得把普通用户的历史结果与 sudo 结果直接作为代码优化对照。
普通用户如需持久访问，可以配置限定用户或专用组的 udev 规则。
必须在新进程中重新检查运行时，因为运行时可以缓存首次访问结果。
