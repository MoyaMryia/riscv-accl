# 2B 草稿词表与回放统计调查

日期：2026-10-17，Asia/Singapore。

## 结论

现用 64k 前缀草稿头对本批中文答案的文本词元覆盖率为 32.16%～34.24%。
先前通过 106 项检查的代码答案，其覆盖率为 99.61%。
这表明词表裁剪对两类输出的覆盖明显不同。

运行跟踪还确认了接受统计混入目标修正词元的问题。
一个中文请求的原始草稿首次接受数为 50／303，即 16.50%。
服务器却报告 140／303，即 46.20%。
多出的 90 个来自检查点回放中的目标修正词元。
该计数也进入低接受率窗口，使本次请求始终保留起草。

本项目记录的加工过程为量化与行复制。
上游模型卡声明 MTP 使用多步训练。
本次先调查词表选择和运行时实现。
微调归因必须另有训练记录或权重比对证据。

## 1．草稿输出头如何形成

本页把追加的输出矩阵称为草稿输出头，把原有预测层称为 MTP 层。
现有 2B 输入来自固定 Unsloth GGUF，文件身份见[来源补证](../../README.md)。

`spacemit/models/tools/add-prefix-head.py` 的第 79～83 行计算每行字节数与复制长度。
该脚本复制 `token_embd.weight` 的前 65,536 行，追加为草稿输出头。
这一步保留量化后的行内容，不执行梯度训练。

原 r3 的 `qwen35.cpp:684–708` 使用该矩阵计算草稿 logits。
当前文件没有 `d2t` 映射，运行时把前缀以外的 logits 补为负无穷。
因此，草稿模型无法直接提出 ID 大于等于 65,536 的词元。
目标模型继续使用完整词表。

固定修订的 [Unsloth 模型卡](https://hf-mirror.com/unsloth/Qwen3.5-2B-MTP-GGUF/resolve/e05864f8066d874d5f85aaff007ae57a2a7d1efe/README.md)将 `Qwen/Qwen3.5-2B` 列为基座。
固定修订的 [Qwen 模型卡](https://hf-mirror.com/Qwen/Qwen3.5-2B/resolve/15852e8c16360a2fea060d615a32b45270f8a8fc/README.md)声明模型经过预训练和后训练。
模型卡中的 MTP 描述为 `trained with multi-steps`。
模型卡提供的用户微调指南属于使用说明。

## 3．RS 0 的回放路径

本次重新运行 `chinese_technical_explanation`，开启 `LLAMA_TRACE=1` 与既有低接受率回退。
答案全文与通用批次对应实验臂一致。
输入为 363 个词元，输出为 241 个词元。
进程和批次退出码均为 0。

原始日志包含 191 条验证事件：

| 项目 | 数值 |
| --- | ---: |
| 原始起草轮次 | 101 |
| 原始草稿词元 | 303 |
| 首次验证接受的原始草稿词元 | 50 |
| 触发检查点恢复的原始轮次 | 90 |
| 后续回放事件 | 90 |
| 回放中接受的词元 | 107 |
| 回放中再次恢复的事件 | 0 |
| 服务器报告的接受词元 | 140 |

每次恢复后，队列包含已接受的草稿前缀及一个目标修正词元。
后续回放的队列长度均等于首次接受数加 1。
回放接受的 107 个词元包含 17 个草稿前缀词元和 90 个目标修正词元。
另有 11 轮原始提案完整接受，共接受 33 个词元。
因此，原始草稿命中数为 `17 + 33 = 50`。
服务器统计则为 `107 + 33 = 140`。

源码对应位置如下：

- `server-context.cpp:3087–3110` 保留恢复后待复用的草稿队列。
- `server-context.cpp:3126–3131` 只对新起草轮次累计生成总量。
- `server-context.cpp:3974–3995` 把目标修正词元留在队列中，恢复检查点后返回。
- `server-context.cpp:4014–4031` 在返回分支之后累计接受数和低接受率窗口。

## 4．低接受率回退为何没有介入

既有条件为每 12 个计数步检查一次。
只有累计接受数小于 9 时才禁用本次请求的起草。
该条件比较的是每步接受词元数。
草稿接受率的分母是生成数，两个指标使用不同的分母。

本次窗口只累计恢复分支之后的完整接受事件。
各完整窗口累计为 `13, 17, 18, 15, 24, 17, 14, 16`。
这些值全部大于等于 9。

按原始提案重建的对应窗口累计为 `1, 6, 8, 4, 16, 7, 3, 4`。
首个窗口实际只命中 1 个原始草稿词元，计数路径却得到 13。
因此，环境变量已经开启，但回放计数使本次请求始终通过既有检查。
