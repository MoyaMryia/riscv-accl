# K1 混合 IME 独立误差检查与便携基建 V7

## 结果与用途

已实现：整数矩阵扩展（IME）的实际轨迹、完整数值核验和混合循环独立误差检查。
已验证：168 个原生完整数值转储与同一 ELF 的 QEMU 转储一致。
336 条实际轨迹完整结束。
62 项工具检查通过。
全部候选均保留，性能评估不使用淘汰门槛。

冻结误差区间覆盖 9/9 个保留组和 27/27 个展开版本。
比值误差因子为 2.1216883936561333，区间很宽。
点预测的方向符号一致性仅为 9/27。
收益绝对误差的观测中位数为 29.540 个百分点，最大值为 50.990 个百分点。
宽区间覆盖不能证明点预测可以安排优化投入顺序。
本轮保留这项失败检查，没有根据后测调整模型或界限。

已实现：新增该失败范例的标准 Python 便携包。
已验证：本机与 K1 原生 Python 的关键预测记录完全相同。
便携包同时保留固定卷积、V5 和 V6 范例。
V5 的 7/9 覆盖缺口仍然保留。
V6 固定对齐循环的 9/9 组覆盖不转移到本轮 IME 范围。

## 固定范围与执行路径

28 个配置组先于本轮性能测量固定。
配置选择种子为 2026101207。
配置包含 1、2、4 条累加链，以及 0 至 9 条独立整数指令间隔。
19 个组用于误差校准，9 个组保留到界限冻结之后测量。
独立函数布局种子为 2026101208。
168 个函数入口与循环入口均通过 64 字节对齐检查。

每个配置包含两个算法臂与 8、32、128 次展开。
对照臂交替加载和点积，候选臂先集中加载再执行点积。
两臂也改变输入寄存器复用，不能把差异只归因于指令顺序。
每次点积读取两个 32 字节向量。
固定输入为全 1 的有符号 8 位整数，累加结果为 32 位整数。
输入、保护区和有效输出均参加完整数值比较。

原生性能测量固定 CPU 0，使用 512、2048、8192 个循环和七轮重复。
校准阶段有 2,394 个有效样本，保留阶段有 1,134 个有效样本。
全部样本保留，计数器没有复用。
周期事件使用 V3 已审计的原始用户态事件 0x22。
频率前后快照为 1,600,000 kHz，不能证明测量期间频率不变。
测量阶段全程在 tmux 中持有板端共用锁。

实际 ELF 的 SHA-256 为 `17ff9ff6a8653478c7471060ebb42cba74a4625a0026aa9cab55ea9d270e5095`。
计划文件的 SHA-256 为 `e61651d6525cb025e2f3a6579d88f7990494e713833a325d2683a9a6f244f937`。
上游 QEMU 11.1.1 对该 ELF 返回非法指令，原始失败归档继续保留。
项目已有的厂商 QEMU 10.0.2 可以执行同一 ELF。
实际轨迹使用 CPU 参数 `max,vlen=256,elen=64,vext_spec=v1.0` 与插件接口第 4 版。
该执行路径用于指令与数值检查，不表示 K1 周期仿真。

本轮点积采用固定 4×4×8 的有符号整数形式。
编码与寄存器约束参考[厂商 IME 规范](https://github.com/spacemit-com/riscv-ime-extension-spec)和[厂商架构说明](https://github.com/spacemit-com/docs-ai/blob/main/en/architecture/ime_extension.md)。
厂商 QEMU 执行参数同时参考 [llama.cpp 的 SpacemiT 构建说明](https://github.com/ggml-org/llama.cpp/blob/master/docs/build-riscv64-spacemit.md)。
本轮实际转储比文档推断提供更直接的数值证据。
全 1 输入检查不能证明任意数据的数值正确性。

## 冻结模型与独立后测

本轮不重新拟合分项模型。
模型身份为 `dd267b9c6d897d0aa025d81d940505a7e34709847eac4fe419f84a4a9ab8b148`。

工具分别计算每个实际展开版本的循环周期。

本轮没有使用展开次数的线性成本假设。
原始拟合残差继续保留。
比值误差界限不校准绝对周期，也不校准完整算子耗时。

每个校准组取三个展开版本的最大绝对对数比值误差。

## 其他机器的快速使用

便携包只需要 Python 3 标准库。
包内提供五个冻结范例和固定访存查询。
工具核验文件收据、模型身份、原始界限和后测数值。
原始 ELF、实际轨迹与原生样本另存在完整归档中。
该便携入口重放既有证据，不替代新算法的轨迹生成与独立校准。

```bash
python3 spacemit/bench/qemu-screen/predictor/model-bundle.py \
  --include-ime-audit --output lab/k1-portable-v7
```

先用外部散列收据核验生成的 `k1-models-v7.tar.gz`。
解包后，在 `k1-models-v7/` 中执行下列命令。
输出目录必须不存在。

```bash
python3 run-examples.py --output ../k1-replay
```

本机与 K1 的关键预测散列均为 `9ebd02ee25ce3c48cb3e6cf5bdbb84dc850d645ae51266661b60811a629906b3`。
本机重放用时约 0.44 s，K1 约 8.11 s。
计时从文件完整性核验之后开始，包含范例子进程与结果核对。
这些主机用时不是被评估算法的 K1 性能。
V6 便携包的本机与服务器重放记录保持不变。
V7 没有完成服务器便携包重放。

新入口 `prepare-ime-mix.py` 生成独立配置与冻结载荷。
`load-use-trace.py --cpu` 可以选择厂商执行路径，默认路径保持原设置。
`audit-ime-mix.py` 检查完整轨迹矩阵、操作数量和全部数值转储。
`ime-mix-evaluate.py` 分开执行误差校准与保留检查。
`ime-mix-demo.py` 重放宽区间与错误方向，防止只展示覆盖通过的结果。
`run-ime-mix-server.sh` 仅完成实现，服务器执行仍待验证。

## 投入顺序与能力缺口

当前最值得补充的是实际目标算法的组合成本与独立误差资料。
本轮证明孤立点积参数不能直接提供混合 IME 调度的可靠方向判断。
后续算法任务可以复用本轮的冻结顺序、逐版本目标和失败范例协议。
实际目标二进制、输入范围和线程配置必须分别记录。
不能将本轮误差因子直接移植到新的算法对。

共享缓存实际流量、多线程同步成本和完整 IME 算子耗时仍待验证。
经 K1 标定的 gem5 后端仍未实现。
任意新算法的独立预测置信度仍未建立。
这些能力缺口没有改记为完成。
当前交付提供可执行评估工具、正反范例和明确的补测顺序。
