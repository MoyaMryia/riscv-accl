## 固定配置

使用原 r3 二进制、2B dv64k Q4_0 模型及原 SPERT、TCM 运行库。
沿用掩码 3、宽 RVV、route 3、B1-r2、C1、4 线程和批量及微批量 32。
上下文为 12288，单槽，F16 KV，RS 快照为 0，日志级别为 4。
温度为 0，种子为 42，关闭思考输出。
输出上限、请求期限和配置定义统一读取 `spacemit/bench/mtp-r3/diagnostic.py`。

每个请求重新启动服务器，不复用提示缓存。
完整请求时间排除模型加载，首词元时间单独报告。
记录预填充、解码、输出长度、草稿接受数、回退事件和进程内存高水位。
服务端实际配置必须与固定配置一致。

## 任务与顺序

固定任务来自 `spacemit/bench/mtp-r3/general_cases.py`。
部署前生成完整的 `cases.json`，连同评估模块一起固定身份。
同一题的三个实验臂读取同一份输入。

| 类别 | 不同任务数 | 任务 |
| --- | ---: | --- |
| 代码 | 3 | Unicode 游程、区间空闲段、Unicode 偏移 |
| 中文文本 | 3 | 客户说明、技术解释、工作交接 |
| 问答 | 3 | 库存计算、服务费计算、规则判断 |
| 长文档 | 3 | 设备数量核对、周报指标、版本与生效规则 |

每题执行直接解码、纯 MTP、MTP 加低接受率回退三个实验臂，共 36 次完整请求。
同类三题轮换实验臂顺序，使每个实验臂各处于首、中、末位置一次。
纯 MTP 关闭低接受率回退，回退臂仅开启既有策略。
两种 MTP 模式均允许单槽起草，草稿上限为 3。

非代码任务要求自然中文答案，不强制 JSON 输出。
短任务附实际相关原文，长文档任务附完整资料。
长文关键证据分布在前、中、后部。
引用编号与事实均来自固定的虚构项目资料。

## 质量与采用规则

代码任务执行既有独立功能检查。
非代码答案保留完整原文，并在完成后隐藏实验臂名称作独立盲审。
自动程序仅提取引用，不把关键词或引用匹配当成事实正确。
非代码质量字段在盲审前保持待评状态。
程序退出码 0 表示测量完成且自动检查通过。
通用采用结论在盲审与分类复算后给出。

盲审按每题来源和要求评分：

| 分数 | 判据 |
| ---: | --- |
| 4 | 事实、引用和代码正确，完成要求，表达清楚 |
| 3 | 无事实、引用或代码错误，有轻微遗漏或表达问题 |
| 2 | 无明确错误，但缺少主要要求或违反主要格式要求 |
| 1 | 存在事实、引用或代码错误，仍有部分有效内容 |
| 0 | 内容为空、不可用或无法完成主要任务 |

采用候选必须同时满足以下条件：

- 相对直接解码，不增加事实、引用或代码错误。
- 质量评分均值下降不超过 0.25。
- 每个任务类别的完整请求时间增加不超过 3%。

每题先计算候选与直接解码的时间比，再在类别内求均值。
输出词元不同只作诊断，不自动判为语义错误。
完整请求时间为主要速度指标，词元吞吐为辅助指标。

## 执行与停止规则

入口为 `general_suite.py`，使用 `run-board.sh` 的 `general_suite` 模式。
批次在 tmux 中持有共用锁，整批时间预算为 21600 s。
功能检查失败仍保留答案，并继续其余请求。
速度下降、低接受率和输出长度变化均不提前终止整批实验。
纯 MTP 臂保留独立结果，回退臂不能替代它。

崩溃、请求超时、配置错误或输入越界触发故障定位。
内部错误直接抛出，不转为有效测量。
失败记录保留，修订必须使用新目录。
