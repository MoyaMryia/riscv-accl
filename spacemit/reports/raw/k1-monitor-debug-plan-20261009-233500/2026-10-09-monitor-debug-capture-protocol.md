# K1 监控段错误增强调试协议

日期：2026-10-09，Asia/Singapore。

本协议在新诊断启动前固定。
本次目标是捕获新故障并减少旧现场的证据缺口。
本次不保证复现罕见故障。
旧 Apport、core、实验输入及已封存原始证据保持不变。
不修改系统 Python、候选算法或生产默认配置。

## 执行与停止条件

所有板端诊断使用独立新目录和 tmux。
整个诊断持有 `document-quality-suite.lock`。
不得同时执行模型、算子计时、构建或另一项长诊断。
短验证每种模式运行一次，指针模式运行一次。
短验证只检查新增夹具与现场保存流程，不作为原故障复现。
正式诊断每种常规模式最多运行 64 次，指针模式最多运行八次。
正式诊断总预算为 7200 s，每个进程预算为 180 s。
CPU 0～7 轮换，指针模式固定 CPU 6。
所有目标进程串行执行。

遇到新的致命信号、指针不一致、非零退出或超时，立即停止后续尝试。
必须分别记录目标 Python、GDB 和外层控制器的状态。
超时或夹具失败不能记为复现了原段错误。
程序正常退出后，GDB 不得再执行 core 保存并将其错误算成目标失败。
新故障保存现场后，先调查原因，再决定是否修订复现夹具。
修订版本使用新目录，并记录修改依据和新哈希。
不得在原目录原样重试至通过。

## 现场保存流程自检

单独的自检目标主动发送 `SIGUSR2`。
该自检只验证信号拦截、完整 core、寄存器、映射、栈和 Python 栈保存流程。
自检目录必须标为 `capture-self-test`。
该自检不能记为真实段错误或原故障复现。
自检通过后才执行其他模式。
GDB 保存现场后终止被调试进程，避免覆盖原 Apport 报告。

## 五种诊断模式

`exact` 按原标准输入方式执行原脚本，读取旧结果目录。
该模式使用 GDB 和 CPU 绑定，环境关闭字节码写入。
这些差异可能改变时序，不能称为历史环境的完整恢复。

`malloc-debug` 仍执行原脚本，目标进程启用 `PYTHONMALLOC=debug` 和 `faulthandler`。
GDB 进程不继承该分配器设置。
该模式检查分配器检测出的边界或释放错误，不等于单独的 Python 调试构建。

`trace` 执行新增包装器。
包装器记录原脚本每行的位置、异常、每次文件读取和垃圾回收事件。
每次实际读取的完整字节按 SHA-256 保留，只解码这一份字节。
每次读取另记前后文件标识、大小和修改时间。
包装器改变对象分配和时序，结果必须单独标注。

`gc-stress` 在包装器内采用垃圾回收阈值 25、3、3。
每个进程最多执行八次脚本，并在各次之后主动收集。
旧目录的输入复制到本次诊断的隔离目录。
同一诊断进程中的夹具线程原子替换两个隔离摘要，模拟变化中的有效 JSON。
包装器只替换原脚本唯一的输入根目录常量，不修改原脚本文件。
旧日志和旧实验目录保持不变。
这一夹具不能重建故障时的原模型负载，也不能排除其他写入模式。

`guard` 使用同一隔离摘要和垃圾回收压力，但保留默认分配器。
仅当 Python 完整文件哈希和原指令字节匹配时安装固定地址断点。
断点分别位于 `0xa123c` 与 `0xa123e`。
前者读取父对象偏移 104 的字段，后者比较寄存器和再次读取的字段。
必须保留最近 256 项检查记录和累计检查数。
任何差异都停止并保存现场，不能仅凭差异归因于硬件。
GDB 断点和单步改变缓存及调度，未出现差异不能排除原故障。

## 新现场的证据

目标遇到 `SIGSEGV`、`SIGBUS`、`SIGILL` 或 `SIGABRT` 时，GDB 在信号递交前停止。
保存完整寄存器、全部原生线程栈、映射、共享库和原始内存窗口。
core 保存关闭默认映射筛选，并包括被排除映射，补存历史缺少的代码页。
包装器另注册 `SIGUSR1`，保存 Python 全线程栈。
如果包装器已就绪，在初次 core 保存后触发该栈记录。
该后续操作可能改变现场，因此初次 core 是原始新现场。
无法保存某项证据时，必须记录具体错误。

必须核验旧输入在诊断前后的哈希。
本次固定 Python 哈希为 `630db2135a33fddb6416e77341ef48e5376f903fcb81d3e0fe36a496a4d0e2d0`。
该哈希不符时，不执行固定地址断点。
必须保存每次尝试的开始、结束、模式、CPU、退出状态及输入字节。
新记录同步到本地新目录，最终保存 SHA-256 收据。
每小时检查一次；状态正常且无可操作变化时保持安静。
诊断结束后区分“新故障已捕获”和“限定尝试未复现”，更新中文报告并暂停本轮监控。
