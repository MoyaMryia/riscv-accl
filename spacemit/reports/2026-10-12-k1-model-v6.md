# K1 对齐循环模型与便携评估基建 V6

## 结果与用途

已实现：按实际展开版本分别建模的循环成本工具。
已验证：9/9 个独立保留组落入先前冻结的误差区间。
三个展开版本的观测覆盖为 27/27，方向判断一致性为 27/27。
收益绝对误差的观测中位数为 0.009 个百分点，最大值为 1.334 个百分点。
这些数值只描述本轮固定循环检查，不能确认总体 95% 覆盖率。
全部候选均保留。

已实现：只依赖 Python 3 标准库的便携模型包。
已验证：本机与项目服务器的全部范例重放结果一致。
关键预测记录的 SHA-256 为 `488b30c73d68cd850e852e10ad41fe6cf1bc547f93929525e535b3f7cce71aa8`。
本机主机重放用时约 0.38 s，服务器约 0.32 s。
该耗时包括完整性核验、四个范例和固定访存查询，不表示 K1 运行速度。

分项模型仍用于诊断，不能提供任意新算法的高置信性能保证。
完整卷积范例具有固定范围内的独立形状检查。
V5 的 7/9 覆盖缺口仍随便携包交付。
本轮没有根据后测结果调整模型或误差界限。

## 模型与独立误差

目标为每个实际展开版本的用户态循环周期，包含循环控制。
工具用循环长度斜率去除固定入口与退出成本。
工具保留这些拟合的残差。
它不再假设循环成本随展开数量线性增加。
8、32、128 次展开分别具有训练锚点。

模型在同一 LMUL、步长、累加链数、算法臂与展开数量下查询向量长度。
模型在两个最近训练锚点之间使用对数成本插值。
范围之外使用端点成本，作为显式经验假设。
这些经验成本不能解释为硬件部件的因果延迟。
新配置仍必须接受独立误差检查。

每个误差校准组取三个展开版本的最大绝对对数比值误差。
19 个组使用第 19 个顺序统计量。
不能把三个展开版本当成三个独立配置组。
冻结的最大误差为 0.06889242567753573。
比值因子为 1.0713209563233168。
声明的 95% 组覆盖依赖固定范围内配置组的可交换性。

一个保留组只有三个版本全部覆盖时才记为覆盖。

## 在其他机器重放

仓库入口为 `spacemit/bench/qemu-screen/predictor/model-bundle.py`。
生成包时会先核验冻结模型身份并重放全部范例。
输出目录必须不存在。

```bash
python3 spacemit/bench/qemu-screen/predictor/model-bundle.py --output lab/k1-portable
```

把生成的 `k1-models-v6.tar.gz` 与外部散列收据复制到目标机器。
先用外部收据核验压缩包。
解包后，在 `k1-models-v6/` 中执行下列命令。

```bash
python3 run-examples.py --output ../k1-replay
```

工具核验包内全部文件，并重算独立检查的区间覆盖。
源码、模型、计划或误差界限身份不同时，重放停止。
历史模型区间漏覆盖时，报告保留缺口，不把候选删除。
主机间比较 `result.json` 的 `portable_prediction_sha256`。
本轮本机与服务器的该值完全相同。

| 工具 | 可以支持的判断 | 当前限制 |
| --- | --- | --- |
| `demo.py` 与分项成本工具 | 指令依赖、成本假设与覆盖缺口 | 不提供新算法预测置信度 |
| `family-demo.py` | 固定卷积算法对的形状范围；观测覆盖 9/9 | 不转移到新算法或二进制 |
| `schedule-demo.py` | 保留 V5 混合指令模型的失败检查 | 观测覆盖 7/9 |
| `neighbor-demo.py` | 固定对齐循环的三个展开版本 | 观测覆盖 9/9 组；不预测完整算子耗时 |
| `memory-reference.py` | 固定模式的有效载荷吞吐率 | 不表示实际 DDR 流量或算法时间 |
| `explain-cost.py` | 声明调度器中的等待归属 | 不表示硬件停顿原因 |
| `shared-cache.py` | 显式几何与交错假设下的共享行重放 | 缺少物理地址、一致性、预取与实际流量核验 |

## 后续投入顺序

当前优先项是为实际目标算子建立匹配二进制的训练、误差校准与保留检查。
固定卷积范例可以作为完整协议的参考。
直接循环范例可以作为组合指令范围的参考。
两者都不能替代新算法自己的独立误差证据。

其次核验多线程同步与共享缓存的实际影响。
V3 的通用分项模型仍对完整卷积的部分方向判断错误。
声明调度器等待和虚拟缓存流量不能填补该项误差。
当前工具已经显示这些缺口，因此可以优先安排对应标定。

完整 IME 混合时序、实际共享缓存流量与新算法置信度仍为待验证。
经过 K1 标定的 gem5 后端仍未实现。
这些扩展不作为当前便携包的已完成能力。
现有证据不足以给出任意算法的统一性能保证。
