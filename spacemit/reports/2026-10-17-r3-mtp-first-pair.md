# r3 纯 MTP 的首对完整代码回答

日期：2026-10-17，Asia/Singapore。

## 结果

在同一 r3 二进制上，2B 纯多词元预测（MTP）的完整请求时间从 123.052 s 降至 94.357 s。
请求时间减少 23.32%，服务端解码吞吐增加 33.16%。
两个回答全文相同，均通过 106 项功能检查。

| 指标 | 直接解码 | 纯 MTP |
| --- | ---: | ---: |
| 输入词元 | 162 | 162 |
| 输出词元 | 508 | 508 |
| 请求时间，s | 123.052 | 94.357 |
| 首词元时间，s | 6.699 | 6.975 |
| 服务端预填充，ms | 6529.687 | 6811.912 |
| 服务端解码，ms | 116350.828 | 87378.935 |
| 解码吞吐，词元/s | 4.366106 | 5.813758 |
| 生成的草稿词元 | 0 | 402 |
| 服务器报告的接受词元 | 0 | 374 |
| 功能检查 | 106 项通过 | 106 项通过 |
| 配对数 | 1 | 1 |

请求时间减少按 `1 - MTP时间 / 直接解码时间` 计算。
解码吞吐增加按 `MTP吞吐 / 直接解码吞吐 - 1` 计算。
本对服务器报告的接受比例为 374／402，即 93.03%。
该字段的统计口径见[回放计数调查](2026-10-17-2b-mtp-head-investigation.md#3rs-0-的回放路径)。
本对收益对应相同的完整答案和相同的输出词元数。
首词元时间增加 0.276 s，单独保留这一观测。

## 配置与检查

生产版本为 `k1-final-20261013-r3`，服务器 SHA-256 为 `f254f174919c0a97ef34366f116705f6d22574cab4c2bfc39928c0d315b5bfbd`。
模型为发布清单中的 `Qwen3.5-2B-MTP-Q4_0-embQ4_0-dv64k.gguf`。
两臂均使用 4 线程、批量及微批量 32、上下文 12288、单槽和 F16 KV。
掩码为 3，宽 RVV、route 3、B1-r2 和 C1 保持编译默认值。
日志级别为 4，RS 快照为 0。

两个请求的 JSON 内容相同。
温度为 0，种子为 42，关闭思考输出。
每次启动新服务器，实际提示缓存复用为 0。
请求均自然停止，服务器正常退出。
计时排除模型加载，保留客户端完整请求时间和服务端阶段时间。

纯 MTP 使用草稿上限 3，关闭低接受率回退。
本轮保留后端草稿采样的默认值。
本次只启用已有功能，没有修改生产源码、二进制或模型。
