## 3. 起点与兼容修改

起点为 SpaceMiT 分支的 `5ad05d8796cb094ee23a3a0152874f8a2b3060f8`。
原版 K1 构建纳入了一个 IME2 文件，构建失败。
第一项兼容修改只删除这一个 CMake 源文件列表项。
修改后的构建无法加载当前模型的缩减 MTP 草稿头。
第二项兼容修改读取 `d2t`，并按存储宽度加载草稿头。
两臂都没有启用草稿解码。

修改只涉及 CMake 列表和 `src/models/qwen35.cpp` 中的张量加载函数。
主输出头、计算图代码和全部计算内核保持原版字节。
兼容补丁 SHA-256 为 `2e8c40a4a056787380e37750bab005777580978d3d9a58d901e911dc12fe01d7`。
两次失败和两项兼容修改的记录都保存在证据中。

两臂都使用 4 线程、批大小 32、上下文 12288、单槽和 F16 键值缓存。
两臂使用相同的编译器和运行库。
测得的收益是从原始软件到最终软件的整体收益。
历史权重量化的变化不计入收益。

## 4. 均衡默认配置的选择

冻结搜索使用一份已核验的 RC1 构建，共 104 次请求。
4 次预检在原版和候选构建上检查两个模型。
掩码阶段在两个模型、两种长度上测试 8 种组合，各两轮。
参数阶段测试 2／4 线程和 16／32／64／128 批大小。
4 次自然回答完成选型检查。
参数阶段保留 4 线程和批大小 32，没有触发额外复验或回退。

均衡分数对两个模型、两种长度、首词元时间和解码耗时赋相同权重。
首词元时间指客户端从发出请求到收到第一个输出词元的时间。
与最低分相差 3% 以内的组合，按冻结规则视为无法区分。
在该区间内，规则优先选择启用候选较少的组合。
掩码 7 的观测分数最低，为 0.8904876472483813。
掩码 3 的分数为 0.915536301962804，处于该区间内，因此规则选择掩码 3。
选型分数相对同构建的 C0 对照计算，与第 5 节的真实起点对照分开。

| 编译默认值 | 取值 |
| --- | --- |
| 工作线程与批线程 | 4／4 |
| 批大小与微批大小 | 32／32 |
| 上下文与槽位 | 12288／1 |
| 缓存与注意力 | F16 键值缓存，闪存注意力开 |
| GPU 层数与解码 | 0，直接解码 |
| 公共路径 | 宽 RVV 注意力和 IME route 3 开 |
| 候选掩码 | 3：B1-r2 和 C1 开，C2-r2 关 |

启动器清除继承的实验变量。
最终服务器只接收模型、别名、主机和端口参数。
运行日志和服务器属性确认了实际默认值。

## 6. 正确性与失败记录

最终构建通过 104 项 route、95 项注意力、432 项 SSM 和 158 项 GDN 原生检查。
转储散列与已核验的 RC1 参考一致。
两个模型共 64 条全词表状态记录逐位一致。
这些记录覆盖 RS 0／3、状态清空，以及上下文 4096 下的 32／33／64／96 前缀。

6 次完整自然回答覆盖两个模型的起点、RC1 C0 和最终版三臂。
每次回答都自然停止，并通过冻结 Unicode 任务的 106 项功能检查。
2B 三臂全文一致，各生成 508 个词元。
4B 起点生成 595 个词元，全文不同。
RC1 与最终版的 4B 回答全文一致，各生成 521 个词元。
两种 4B 文本都通过功能检查。

r1 交付通过数值检查，但参数解析器的 GPU 默认值断言失败。
r2 修正了该断言，但启动时自动使用 4 个槽位。
r3 在源码中把服务器默认槽位固定为 1，并完整重新构建。
两个失败版本的源码、构建身份和日志都已保存。

旧的三项全开组合在 4B／2048／65 上相对 B1 退化 3.0220477%，该结论在原测量条件下保留。
IME 标量调度候选未通过性能初筛，继续排除。
GPU 卸载和分页分配的内存收益没有合格结果。
预测器的误差和宽区间与实测模型结果分开记录。

最终搜索测试 B1-r2、C1 和 C2-r2 的 8 种组合，都没有启用 MTP。
此前的 MTP 试验在两个模型上都通过了相对质量门槛。
该试验的六题总耗时，2B 减少 8.63%，4B 减少 15.22%。
MTP 保持关闭，原因是该试验另设了绝对可用性门槛。
直接解码在区间代码题和 2B 算术题上同样未通过该门槛。
[下一步计划](2026-10-16-next-plan.md)将在 r3 上按相对质量门槛和分类速度门槛重新测试 MTP。
