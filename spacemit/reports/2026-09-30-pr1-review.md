## Findings

### P2: matrix output audit accepts missing hashes and differences between arms

`spacemit/bench/verify-results-matrix.py:153–155` checks uniqueness of hashes
only within each report row. All missing hashes produce the singleton set
`{None}`, which passes. It also never compares the RVV-off and RVV-on rows
whose report claims exact output agreement; the parsed `audit_c` is unused.

Reproduced on temporary copies of the archives while preserving timing cells:

- Replaced all eight RVV-on short-run token hashes with a different common
  value. The complete 21-row matrix still exited 0 and reported `hash-ok`.
- Replaced all 16 short-run token hashes with null. The matrix still exited 0.

Require nonempty hashes and compare the appropriate paired arms before
validating an `Exact` claim. A single complete arm can establish completion
but cannot establish agreement with another arm.

### P2: confidence-interval lookup is not consistently conservative

`spacemit/bench/paired-stats.py:33–39` selects the next larger table key for
missing integer degrees of freedom. For df=11 it returns 2.179, below the
Student t critical value 2.200985. For df=30 it returns 1.960 rather than
2.042272. These choices narrow the stated 95% interval.

The call also floors fractional Welch degrees of freedom first. This can be
very conservative at the current two-launch sample sizes. For the archived
M4 pp128 comparison, df=1.311984 and the precise Student t critical value is
7.385864, whereas the PR uses 12.706. The PR's interval is
[-0.0553, 0.6608] tok/s; the standard Welch interval under its independent-arm
assumptions is [0.09465, 0.51089] tok/s. Thus its statement about whether that
interval contains zero depends materially on this approximation. Two launches
per arm remain insufficient for a robust general performance recommendation.

Use a precise Student t quantile, or document and implement a genuinely
conservative bound rather than labelling an inconsistent lookup a Welch 95%
interval.
