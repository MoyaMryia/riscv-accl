# Per-request low-acceptance fallback on SpaceMiT X60

Date: 2026-09-24. The opt-in `0006-low-acceptance-fallback.patch` was built in an isolated official `spacemit-com/llama.cpp` worktree from `6562c22`. The same binary, model, prompt, and runtime were used for control (`SPINE_SPEC_LOWACC=0`) and adaptive (`SPINE_SPEC_LOWACC=1`) runs. The only changed process setting was that environment variable. The original `port-gdn` checkout and build were not modified.

The gate watches accepted draft tokens over 12 target verification steps. If that window yields fewer than nine accepted tokens, it stops drafting for the rest of that request. The decision resets when a new request starts. This changes scheduling only; the target model still samples all output tokens. The patch is off by default.

Both models used the tested `-dv64k` Q4_0 MTP GGUF, four threads, context 8192, one slot, batch/microbatch 32, flash attention, `SPINE_SPEC_RS=1`, spine-tcm in `LD_LIBRARY_PATH`, MTP draft maximum 3, `temperature=0`, seed 42, and `cache_prompt=false`. Each condition started a fresh server. The three prompt families requested 128 tokens, and all results below are server decode tokens/s from a single pass unless called a two-pass mean. Greedy output hashes matched within each prompt and model.

| Model and prompt | Control | Adaptive | Draft acceptance control → adaptive |
| --- | ---: | ---: | ---: |
| 2B English | 6.487 | 6.514 | 82/131 → 82/131 |
| 2B code | 5.704 | 5.725 | 76/153 → 76/153 |
| 2B Chinese | 3.588 | 4.274 | 45/243 → 6/36 |
| 4B English | 3.348 | 3.345 | 84/126 → 84/126 |
| 4B code | 2.829 | 2.826 | 77/149 → 77/149 |
| 4B Chinese | 1.693 | 1.922 | 43/251 → 5/36 |

The Chinese comparisons were repeated in reverse process order. Two-pass means: **2B 3.588 → 4.263 tokens/s (+18.8%)** and **4B 1.690 → 1.924 tokens/s (+13.8%)**. The adaptive run triggered after 6 accepted tokens in 12 steps on 2B Chinese and 5 in 12 on 4B Chinese. It did not trigger on the measured English or code requests.

The existing combined `ngram-mod,draft-mtp` setting was also checked on 2B with 160-token outputs. C++ near-copy: 10.358 → 10.373; Python edit: 6.974 → 6.988; prose: 5.215 → 5.223 tokens/s. None triggered the fallback, and all response hashes matched. A same-server Chinese-then-English sequence verified reset: Chinese triggered at 4.264 tokens/s, followed immediately by English with normal 82/131 draft acceptance at 6.516 tokens/s.

For context, disabling all drafts in the **same RS-configured server** gave 4.431 tokens/s on 2B Chinese. The adaptive result is close to that ceiling after paying for its initial 12 verification steps. A separately configured direct server previously reached about 5.10 tokens/s; switching an existing RS context to that direct configuration mid-request was not attempted.

## Reproduce

Apply patch 0006 after patches 0001–0004 using `spacemit/apply-patches.sh CHECKOUT --lowacc`, build, and run `spacemit/bench/bench-server.py` on the board. Compare separate runs with `SPINE_SPEC_LOWACC=0` and `SPINE_SPEC_LOWACC=1`; use `--modes mtp --prompt-set frspec --n-predict 128` and the same model path. For the combined-mode check, use `--modes combined --prompt-set ngram --ngram-min 16 --ngram-max 16 --n-predict 160`. The archived [raw JSONL and gate events](raw/2026-09-24-lowacc/) are the complete measured records for these runs.

These are two repeats of one weak-acceptance Chinese prompt and single passes of the other prompts on one board. The change is an opt-in candidate, not evidence for a universal default or high-concurrency gain. The existing high-concurrency gate should be measured separately if this patch is used there.
