# 2B 解码请求路由原型

本目录提供小型请求分类器和独立 HTTP 实验代理。
分类器识别代码、问答、文本写作和资料任务。
策略层选择解码路径，后端继续使用原 2B 模型。
本次训练只涉及分类器，不训练 Qwen 权重。

## 当前建议

已微调的小型 BERT 分类器、原生客户端和训练命令见[BERT 说明](BERT.md)。
新测试集准确率、K1 原生一致性与分类耗时见[微调实测](../../reports/2026-10-18-2b-bert-classifier.md)。

生产继续使用直接解码；两路代理保留为独立实验和手工对照入口。
真实端到端结果见[两路实测](../../reports/2026-10-18-2b-router-e2e.md)。
传入 `--full` 可以增加完整词表 MTP，用于三路对照。

既有四题的直接解码总时间为 620.330 s。
逐题选取最快路径时，两路总时间为 591.583 s，三路为 582.148 s。
第三路相对两路仅再减少 1.59%。
这些值使用既有配对数据，见[完整头实验](../../experiments/2026-10-17-2b-full-head-ablation.md)。

## 分类与策略

分类器使用字符 2、3、4-gram、确定性哈希和四类线性 softmax。
特征取最后一条用户消息的前后窗口，每端最多 256 个字符。
短文本保留原文，不重复重叠窗口。
模型使用 4096 维特征，压缩后为 161262 字节。
训练入口为 `train.py`，固定任务集为 `tasks.jsonl`。
任务集包含 80 条训练请求、24 条开发请求和 24 条测试请求。

| 类别 | 两路 | 三路 |
| --- | --- | --- |
| 代码 | 前缀 MTP | 前缀 MTP |
| 问答 | 直接解码 | 完整词表 MTP |
| 文本写作 | 直接解码 | 直接解码 |
| 资料任务 | 直接解码 | 直接解码 |

分类标签描述任务，最快解码路径由配对测量判断。
模型分数用于诊断。
实验默认按最高分类分数选类，再读取策略表。
`--score-guard` 可启用模型中保存的分数门槛，对低分请求使用直接解码。

## 使用实验代理

先由一个外层进程持有板端共用锁，再启动本次实验的全部后端。
各后端不重复取得同一把锁。
核对原生启动参数。
锁路径和运行库设置见[部署指南](../../DEPLOYMENT.md)。
直接解码后端关闭 MTP。
前缀后端使用发布的 dv64k 文件并启用纯 MTP。
完整头后端使用同共享权重的完整头文件并启用纯 MTP。
后端由独立入口启动，代理读取这些地址。

启动两路代理：

```bash
python3 spacemit/serve/decode-router/proxy.py \
  --model spacemit/serve/decode-router/model.json.gz \
  --direct http://127.0.0.1:18101 \
  --prefix http://127.0.0.1:18102
```

三路实验额外传入 `--full http://127.0.0.1:18103`。
代理固定监听 `127.0.0.1`，默认端口为 18090。
客户端使用 `/v1/chat/completions`。
自动路由使用 `X-Decode-Mode: auto`，省略该头时同样自动选路。
手工对照使用 `X-Decode-Mode: direct`、`prefix` 或 `full`。
手工模式旁路分类器。
未配置的手工模式返回 400。

代理保留请求正文的原始字节。
它不修改 messages、温度、种子或输出上限。
它按可用字节转发响应，并保留内容编码、语言和缓存控制头。
后端响应必须提供 Content-Length 或标准 chunked 编码。
代理使用 HTTP/1.1 chunked 响应。
已检测到的上游截断会产生不完整传输，代理不会补写成功终止块。
后端失败后不重试，也不转到另一解码路径。
所有后端请求经过同一个互斥门，避免多组 4 线程同时解码。
`/health` 返回代理状态，后端状态由各后端检查。

日志记录类别、分数、路径、分类耗时和排队时间。
日志不记录请求正文。
日志中的 `relayed` 表示字节传输结束。
客户端必须继续核对 finish_reason 和答案质量。

## 复现分类器与回放

以下命令使用新输出目录：

```bash
python3 spacemit/serve/decode-router/train.py \
  --tasks spacemit/serve/decode-router/tasks.jsonl \
  --output lab/router-train-rerun
```

`evaluate_routing.py` 测量分类开销，并读取已完成的三臂配对数据作回放。
其输出区分逐题最优值、模型选择的路径和加入分类开销后的回放估计。
原生后端端到端测量继续保留直接解码、前缀 MTP 和完整头 MTP 对照。

## 适用范围

实现：Python 标准库、文本请求、独立实验代理、两路或三路静态后端地址。
模型样本：128 条合成任务，按 80／24／24 拆分。
既有速度回放：四类各一题，共 12 次原生请求。
生产二进制、Qwen 权重与默认启动入口保持原状态。

- 待验证：实际请求分布与分数门槛。阻塞：模型只使用构造任务，0.65 是原型初始门槛。解除条件：收集独立新任务，校准门槛并冻结后评估。
- 两路真实测量与非代码盲审任务见[实测范围](../../reports/2026-10-18-2b-router-e2e.md#适用范围)。
- 待验证：三路自动路由净收益。阻塞：当前真实代理测量使用 direct、prefix 两路。解除条件：固定收益监督策略，核对三路常驻后端，再用独立请求测量完整时间与质量。
- 待验证：多轮缓存与并发。阻塞：本原型采用全局串行门。解除条件：单独测量多轮命中、排队和并发，并沿用项目质量采用规则。
